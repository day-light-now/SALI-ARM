## 新接口

`commission_supported_trial.py --plan <JSON>` 默认只读预览；执行仍需原有三个确认参数与 `--execute`。计划明确使用 `absolute_deg`（软件绝对角度）或 `relative_start_deg`（每个点均相对本次起点，不逐点累加）。每个点含 J1～J4 四个角度、移动时间、停留时间。五次插值峰值限速按每段检查；完整 URDF 限位、43 秒客户端预算、驱动 45 秒会话上限均保留。

出程与后续点可分别指定不同角度；最后一点不强制返回零位。示例明确返回本次起点。没有自动循环或自动重试。

到位判据：每点停留末 0.3 秒内采样跨度至少 0.2 秒，四轴各自最大绝对误差均不超过 0.5°。缺样或误差超限均不算通过；标准动作终点容差为 0.5°。各中间点判据在动作完成后统一核算，沿途实时异常停止仍由现有驱动保护负责。采样时间是 ROS 客户端接收时刻，非驱动硬件时间戳。记录原计划、SHA256、逐点误差与跨度、实际正负行程范围、最终偏移、停止确认。

## 操作

保留现有驱动窗口。在另一个 Ubuntu 操作窗口：

```bash
source /home/xuyu/slaihand_waypoints_ws_20261104/install/setup.bash
ros2 run slaihand_bringup commission_supported_trial.py --plan /home/xuyu/slaihand_waypoints_ws_20261104/install/slaihand_bringup/share/slaihand_bringup/config/supported_waypoints_example.json --hold-seconds 1
```

预览确认路径和机械条件后，用户手动 reset，再为同一命令添加 `--execute --ack-supported --ack-clearance --ack-native-output`。示例相对当前起点 [5,3,-3,5]°，9秒移动、1秒停留，再9秒回起点、1秒停留。每次执行重新读取当前位置，不自动回到上一次起点。

停止入口仍是 `/slaihand/stop_all`；请求接受不等于失能已确认。UNKNOWN 时不重试使能，保持支撑并现场切电。
