## 2. 自由拖动就绪判据（驱动）

- 现状：`hold_ready = 静止 0.5 s && 增益/前馈渐入完成`。自由拖动中操作者持续拖动手臂，静止条件永不满足，客户端等待超时且记录器无法打开窗口。
- 修改：**自由拖动模式**下 `hold_ready` 只由前馈渐入完成决定；正常位置保持模式保留“静止 0.5 s + 增益斜坡”语义（该语义是抓取/保持就绪判断，不能删除）。
- 依据：任务书“复核驱动自身的自由拖动就绪语义”；参考分支 `438a05a` 的第一项修改。
- 反例先行：PTY 中注入非零反馈速度（0.2 rad/s），旧代码 `hold_ready=0`、新代码 ramp 后 `hold_ready=1`。
- 记录器侧：首个窗口仍要求 `hold_ready`（打开时成立即可），窗口内继续检查使能/新鲜/自由拖动/阶段/身份/命令/限位。

## 3. 自由拖动反馈速度门槛（独立评估，不随就绪修复默认上线）

- 参考修改：自由拖动时跳过 `FEEDBACK_SPEED` 反馈速度门限，仍保留温度、反馈年龄、周期间隙、MIT 时序、URDF 限位、表示范围、会话超时与全轴停止。
- 风险：手拖漂移/失控时不再有 1 rad/s 速度门限兜底；大角度模型外推误差可能加速漂移。command_id=3 的历史事件正是 1.105 rad/s 触发的保护性停止。
- 处理：作为**独立提交**实现并用 C++ 反例覆盖（自由拖动 1.2 rad/s 不停止、位置模式 1.2 rad/s 仍停止），交付建议由 Codex/用户单独决定是否现场应用；不把该修改包装成就绪修复的一部分。

## 4. 网页当前位置静态采样（单一所有者有限操作）

流程（同一 `supported_capture` 操作内串行，跨操作必须重新预览）：

1. 用户托住机械臂摆到目标姿态 → 用现有自由拖动/示教入口结束 → 等待新失能确认 → 用现有“软件复位”进入新鲜 DISARMED。
2. 网页预览：冻结新鲜实际姿态为位置保持起点，展示四轴角度、完整限位、驱动运行身份（boot/哈希/load_id）、Kp/Kd、当前 α 基线是否满足（α=0 才可进入拟合）、有限时间（撤手等待 ≤60 s、静态窗口 2 s/10 帧、总预算）。
3. 启动：服务端校验票根/起点漂移 0.5°/身份/停止纪元，固定 argv 启动受保护客户端；客户端 `arm_supported_current_pose`（正常位置控制，Kp=160/Kd=5）→ 等 stage=5 且 `hold_ready` → 记录模式、目标、回执。
4. 页面显示“位置保持已就绪，托稳后缓慢撤手”；用户撤手且防坠支撑不承重后勾选“已撤手”并点击按钮；面板校验 operation/running/阶段/新鲜/命令/boot/身份/停止纪元/未重复后，写一次性 ack 文件（schema + operation_id + command_id + boot_id + identity_sha256 + stop_generation + nonce + operator_disengaged）。
5. 客户端等待 ack 文件（有限超时），校验内容与当前 command_id/boot/identity 一致且仍保持，才采集静态窗口；窗口按既有标定资格（完全使能、逐帧新鲜、间隙、速度/位置稳定、命令一致）。α≠0 的样本允许采集但标记“仅诊断、不进入拟合”（既有 `calibration_core.exclusion_reason` 拒绝 alpha≠0）。
6. 停止优先：采样后先调用全轴停止并确认新失能，再做文件 I/O（原始 JSONL 独占创建、只读、来源身份、质量窗口、残差只读报告）；任何阶段的停止都会终止客户端并拒绝迟到 ack。
7. 结束：页面展示质量、α 基线、拟合资格、原始文件、模型预测/实测/残差（只读），失败码与原因如实显示。

拒绝矩阵（服务端 + 客户端双重）：跨停止纪元、换 boot_id/command_id、身份哈希变化、反馈过期/失联、阶段非保持、未就绪、重复 ack、操作已结束后的 ack、窗口不静态、采样后 ack、心跳丢失、UNKNOWN。
