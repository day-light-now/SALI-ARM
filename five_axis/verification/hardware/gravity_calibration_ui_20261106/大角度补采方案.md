## 1. 为什么需要补采

- 失败操作 `fcc72ec323c24e38`：客户端在位置补偿保持时等待 `hold_ready` 超时，0 帧；就绪语义已由本轮驱动修复解决（自由拖动改为前馈渐入完成即就绪），但该记录本身没有可用样本。
- 完整记录 `36dcda3795794b61`（2502 帧、25 s）证明能力范围：J1 40.61～66.27°、J2 −7.24～48.09°，峰值 0.971 rad/s；但自由拖动含未知人手力矩，**不能**作为拟合样本。
- 候选模型 `gravity_identified_candidate.json` 训练覆盖仅 J1 −17.40…16.79°、J2 −2.75…31.45°（J3 −22.9…22.9°、J4 −32.5…32.6°）；观测到的大角度已明显外推。只读报告给出外推预测与风险：见 [大角度残差报告.md](大角度残差报告.md) 与 `evidence/large_angle_coverage_report.json`。

- 位置保持期间按既有静态资格采集：四轴逐帧使能、反馈逐帧新鲜、窗口 ≥1 s、速度/位置稳定、间隙 ≤0.05 s、`command_id` 单一、`alpha=0`、运行身份 verified。

## 3. 操作步骤（现场，由用户/Codex 执行）

1. 使用独立候选构建（本工作树 `src` 构建；隔离域 176/177 仅用于离线验证），确认驱动 `alpha=0.0`、Kp=160/Kd=5、运行身份与候选档案资源哈希一致。
2. 确认 J1/J2 大角度区域净空、线缆余量；机械臂处于低姿态，准备防坠支撑与现场断电手段。
3. 控制面板 → 标定组选择 L01 → 载入自动采集计划（不运动）→ 预览完整 12 路点 → 三项确认 → 执行；同时有界停止随时可用。
4. 每组结束等待新失能确认；检查原始文件和窗口质量；任何窗口不合格立即停止并重采。
5. L01–L04 完成后，再执行 V02（独立验证）；**V02 不得参与拟合**。
6. 采集完成后离线运行拟合工具（沿用 `fit_bidirectional_campaign.py` 的几何回归/配对中点流程，扩展到 L01–L04 + V02），生成独立候选档案 `gravity_large_angle_candidate.json`，交 Codex 复核。

## 4. 拟合与发布门槛

- 新候选状态只能是 `LOCAL_OFFLINE_CANDIDATE`；不得自动部署、不得覆盖现有候选。
- V02 配对中点留出 RMSE ≤ 0.1576 N·m，且逐轴最大绝对误差不劣于现有候选；否则不生成新参数。
- 报告可辨识秩与条件数：现有候选秩 8/16；若新增样本仍停留在同一有效基方向，秩不提升必须在报告中说明，不能宣称“已辨识全部连杆参数”。
- 原始数据独占创建、只读、来源身份与 sha256 写入报告；新参数与旧候选的对比表一并交 Codex。

## 5. 本轮交付边界

- 本轮只有**计划与只读分析**：没有现场大角度新样本，因此没有新参数；`gravity_large_angle_candidate_plan.json` 是独立候选档案的计划/门槛占位，`effective_coefficients` 为 null。
- 网页“当前位置静态采样”卡片用于单姿态诊断/补充采样；成组正反来向补采仍走校准组自动计划，二者共享静态资格与身份绑定。
- 外推预测只用于选点与风险提示，不是重力矩测量。
