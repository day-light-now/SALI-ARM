# 独立实机负载补偿标定工具

入口：实机负载补偿标定.bat。普通OpenArm原生MIT入口不提供补偿开关，仍为原来的零FF请求控制。禁止同时占用COM9。

此工具只用实机位置、速度、实际下发MIT字段；不读取仿真重量/质心/重力模型。每次只使能所选J1–J4的一轴，在当前姿态保持30秒，不自动转动到标定点或回零，不写电机参数。J5不查询、不使能。

操作：
1. 先完成J2第一个姿态点验证，其他轴先不启动。确认可靠防坠措施、所选轴局部无干涉，能立即切电；不要在运动范围内用手承担防坠。
2. 关闭其他软件的串口连接，打开本工具，选择J2，点“只读检查”。四轴均应模式1/TIMEOUT2000/正常失能。
3. 填写姿态标签、实际负载、到该姿态的方向（模型正向/反向/未记录）。手动摆姿需在已确认失能并有支撑时进行；工具不自动变姿态。
4. 必须能确认采样期间托架/外部支撑不分担待标关节的静态负载，否则不能作为自身负载标定。不能确认这点就不采样，不为标定撤去防坠保障。
5. 落实三项现场条件后，点“所选轴保持30秒并记录”。全程关注机械状态；异常点停止，必要时现场切电，失败不重复启动。
6. 稳定窗口和新反馈失能确认均通过才自动入档。结束后发结果JSON；先验收第一个点，再安排后续姿态和其他轴。

记录：tmp/load_calibration/每次JSON及JSONL；合格点追加verification/hardware/load_calibration/records.jsonl，不覆盖旧记录，不自动应用。

“一次标定”指一次完整采集流程。每轴需多个实际工作姿态，尽量包含同姿态正/反向接近的重复点以观察摩擦；四轴姿态共同影响负载力矩。一个点只适用于记录的姿态，不能认作全行程补偿完成；改变零位、安装方向、末端负载或结构后需重新核对。

算法与边界：Kp160/Kd5原生PD，有界积分Ki12Nm/(rad·s)、前馈≤2Nm、变化≤0.5Nm/s；增益爬坡期间不积分，速度>0.05rad/s或误差>1.5°冻结，0.05°死区内保持；停止和新试验清零。总请求估算门槛J1=8Nm/J2=10Nm/J3/J4=2Nm，均不是驱动连续硬限幅。速度中止1rad/s、温度/时效/四轴FD+新反馈确认等保留。标定票据只允许保持，拒绝轨迹。J1机械限位问题仍未解决，本工具不批准行程试验。

合格点标准：最后两秒有效使能反馈覆盖至少1.5秒、四轴姿态各自变化≤0.15°、所选轴速度≤0.05rad/s、请求估算极差≤0.5Nm、积分偏置极差≤0.15Nm，且30秒保持完成、最终确认失能。不要求驱动位置恰好等于目标，因为记录的是实测保持姿态。

记录量是“驱动请求在反馈状态下的估计”，不等于轴端测力或纯重力。摩擦、线缆和外力可能混在其中；当前只做真实数据建档，不自动拟合或部署全行程补偿表。
