# SLAI 桌面上位机界面设计方案

日期：2026-10-30。目标为当前四轴主机械臂，不包含腕部开发。J5可物理接入，但本轮软件不向ID5发送任何请求或控制指令。

## 结论

以松灵PiPER的关节调试和设备状态分区、Seeed RoboController的桌面调试与分步标定、OpenArm的RViz/MoveIt模型及轨迹预览为参考，设计SLAI原生桌面控制工作站。界面组织和交互可借鉴，不能把这些产品的驱动、硬件零点命令或控制增益直接用于SLAI。首版Tk只读表格是通信验证工具，不作为最终界面。

本文件为设计方案，不表示后述控制功能已实现。本轮未改运行中的只读程序、发送权限或电机参数。

## 已核对的官方参考

1. 松灵PiPER开源桌面界面： https://github.com/agilexrobotics/Piper_sdk_ui 。其README列出CAN连接、使能/失能、单关节控制、状态读取、安装方向与版本显示等功能。该例程使用PyQt5与Linux CAN环境，不是可直接连接Windows达妙USB2CAN的驱动。不能照搬其Random、All Set Zero、Go Zero或Stop行为。

3. OpenArm ROS2/MoveIt控制： https://docs.openarm.dev/api-reference/ros2/control/ 。官方展示RViz的模型、Joints目标、Planning和轨迹预览。不是一个可以直接改品牌的统一Windows上位机。其MoveIt集成页面明确仍在开发。

## 设计原则与视觉系统

采用浅色工程工作站而不是营销仪表盘。模型和关节操作是中心，设备参数与诊断退到相应标签页，不铺满提示文字与相同的装饰卡片。

- 基础背景 #F3F5F7，工作面 #FFFFFF，主文字 #1B2D42。
- 主操作色 #265DA8；未配置/待验证警告 #A15C00；真实故障和危险操作 #B42318。颜色同时配中文状态，不只用红绿灯表达。
- 中文优先微软雅黑UI，拉丁文本Segoe UI，数值尽量固定小数与列宽；内部计算仍为rad，常规操作显示°。
- 固定顶栏展示当前后端和输出权限。实机、离线回放和仿真必须明显区分，不能在同一位置悄悄替换数据源。
- 左侧紧凑导航，中间大模型区，右侧固定关节操作区，底部可折叠遥测/日志区。适配常见1920×1080与较小窗口。
- 目标值与实际反馈分开显示；模型实际姿态使用反馈，目标预览采用不同轮廓和标签。不伪造实时连接、轨迹、碰撞通过或保护验收状态。

## 主界面布局

```text
SLAI 控制台 | 后端：实机/只读 | COM9 | 在线 4/4 | J5 禁发送
导航       |                                          | 当前关节 J3
设备概览   |          SLAI 实际模型与坐标轴             | 实际角度 / 目标角度
关节控制   |          实际姿态 / 目标预览               | 点动步长、速度、输出限制
零位与方向 |          正面 / 侧面 / 适应视图            | 负向点动 / 正向点动
动作轨迹   |                                          | 明确执行 / 停止
动力学实验 |------------------------------------------| 就绪条件与拒绝原因
日志诊断   | 关节状态表 / 角度曲线 / 反馈力矩 / 事件日志 |
           | J1 J2 J3 J4：反馈年龄、状态、温度、模式    |
```

只读版本不显示可用的运动按钮。未来控制页未接入前显示“未接入实机控制”和具体原因；不以假按钮模拟已完成的功能。软件停止不命名为硬件急停。

## 功能分区与实施顺序

| 页面 | 第一阶段 | 后续能力及前置条件 |
|---|---|---|
| 设备概览 | 连接、断开、ID1至4、模式、温度、故障、超时、原始/软件角度、反馈年龄 | 多设备配置、异常快照；断开遥测不自动等价于机械失能 |
| 关节控制 | 先展示当前角度和目标预览，不输出 | 受限点动、有限时长轨迹、目标与实际误差；每轴输出限制和回退行为明确后开放 |
| 零位与方向 | 从当前姿态采集软件零位候选、正向手动采样、比较确认、保存本地映射、保留原始报文 | 不写电机零点，不把“归到零位”和“将当前位置记零”混为一个按钮 |
| 动作与轨迹 | 从反馈记录命名姿态，离线查看，标记适用轴和映射版本 | 平滑预览、逐段执行、取消、回放；没有碰撞模型不能宣称无碰撞 |
| 动力学实验 | 接入已有MuJoCo三模式实验，明确仅仿真，显示暂定质量与惯量 | 实机重力补偿、阻抗/拖动需单独验收，不能因界面存在就开放 |
| 日志与诊断 | 中文事件、原始CAN、状态变化、文件导出、连接历史、故障快照 | 参数写入放独立高级区，需准确型号和版本，不做隐式恢复出厂或校准 |

建议用PySide6作为正式桌面界面，保留已验证的达妙USB2CAN只读封包与软件映射。原生3D视图的Qt/VisPy等依赖需先评估，不预先宣称已安装。现有ROS/RViz与MuJoCo实验独立保留，再通过明确适配接口逐步集成，不把Linux SocketCAN代码直接当成Windows串口驱动。

## 当前数据应如何诚实显示

用户本轮截图中四轴反馈4/4，均为正常失能；J1为位置速度模式，J2至J4为MIT模式。TIMEOUT都显示0，应该在保护栏目提示“未配置非零通信超时”，不是把它画成电机正在故障。此前J3试验的2000计数没有保存Flash，重启后必须重新核对。

只有当前新鲜反馈才能显示为实时；过期立即失效。相对零位数值不接近0并不自动表示映射错误，也可能是实物没有摆回参考姿态。人工零位精度未测量，J1机械限位问题尚未关闭。J3近零/低力矩试验没有完成主动回位，不能显示“回零完成”。

## 验收要求

1. 不连接串口就能浏览界面；启动不使能，不向J5发请求；所有真实功能与后端能力相符。
2. 新界面只读阶段复用并继续通过现有发送白名单、分帧、角度换算、过期和冲突测试；不为了换皮增加写指令。
3. 三维实际模型跟随反馈，断线/过期有清晰状态；无数据时不拿演示动画冒充实机。
4. 软件零位采集与运动回零独立；保存映射显示预览并留版本，绝不暗中保存电机零点。
5. 运动功能独立验收后再开放，后台控制与界面线程分离；UI卡顿、断线、退出、停止均有明确处理，硬件断电措施不能由界面替代。
6. 调研软件的开源许可逐项检查；目前仅借鉴设计和工作流，没有复制或运行第三方电机控制代码。
