# SLAI桌面上位机界面参考调研

核查日期：2026-10-30。用户要求参考 OpenArm、松灵和“seed”；本轮将最后一项暂按 Seeed Studio 理解。本文只整理官方公开资料与设计建议，没有安装第三方控制工具、连接串口或改变现有程序权限。

## 结论

最适合当前 SLAI 的组合是：借鉴松灵的设备与控制功能分区、Seeed 的逐关节调试与校准管理、OpenArm 的模型视图及规划预览流程。它们不是同一套软件，也不能把各家的控制按钮或通信后端直接复制到我们的四轴硬件。

当前程序是 Windows USB2CAN 只读监视器。新界面应保留 J1至J4 的只读白名单、反馈过期处理和独立软件零位，J5维持禁止发送。界面改版不等于授权增加使能、清故障、改参数或整臂运动。

## 官方参考与证据边界

### 松灵 AgileX Piper_sdk_ui

官方仓库提供实际 Qt 上位机及功能表：CAN端口选择和激活、使能状态、关节控制窗口、关节滑条、状态信息、限位读取、安装方向和夹爪等。其环境说明以 Ubuntu、Python3.10、PyQt5、python-can 与 piper_sdk 为基础，不能把 Linux can0 后端原样用于本机 COM9 USB2CAN。我们可参考其分区，不直接照搬其复位、随机运动、硬件设零和默认参数恢复动作。

来源：[松灵官方 Piper_sdk_ui](https://github.com/agilexrobotics/Piper_sdk_ui)，重点 README 的“2.2 功能”；界面相关源文件为 piper_ui.py，仓库 image 目录包含相关素材。

补充来源：[松灵官方 PiPER 产品页](https://www.agilex.ai/products/piper)。旧版 Windows ArmRobotUA 快速手册的官方搜索结果可确认通讯、垂直菜单、速度比例、使能及停止区，但本轮直接取该PDF遇到TLS或超时，因此不将其截图称为已完成目视核查。本轮以可完整读取的 Piper_sdk_ui 功能表为准。

### Seeed Studio Seeed_RoboController

官方项目是 SO-ARM/LeRobot 的图形调试与校准工具，支持 Windows、Ubuntu、macOS，采用 Qt/PySide6。Wiki 展示端口选择、设备识别、逐舵机控制及状态、校准文件管理、高级寄存器工具等实际截图。适合借鉴单关节卡片、设备概览和软件校准工作流；它使用 FTServo/SO-ARM 体系，不是达妙电机控制库。

来源：[Seeed 官方图形调试教程](https://wiki.seeedstudio.com/lerobot_steering_gear_debugging_tool/)、[官方开源仓库](https://github.com/Seeed-Projects/Seeed_RoboController)。

实际截图来源（官方Wiki原图，未复制到本工程）：

- [整体调试界面](https://files.seeedstudio.com/wiki/robotics/projects/lerobot/debug_tool/debug_tool.webp)
- [单舵机控制示例](https://files.seeedstudio.com/wiki/robotics/projects/lerobot/debug_tool/14.png)
- [高级工具示例](https://files.seeedstudio.com/wiki/robotics/projects/lerobot/debug_tool/16.png)

这些界面也包含硬件写中位、使能及恢复等操作。本项目不能因参考界面，就把这些写操作开放到实机。

### OpenArm

官方 ROS2 控制文档使用 RViz/MoveIt2：Joints 设置关节目标、Planning/Goal State 管理目标、Plan 先预览路径。官方也明确区分 fake hardware 与 real hardware，相关集成仍在发展。这可用于设计“实际姿态与目标姿态分开”“先预览、后执行”，不能据此声称已有一套统一、独立的 OpenArm 官方桌面示教软件可直接迁移。

来源：[OpenArm ROS2 Control](https://docs.openarm.dev/api-reference/ros2/control/)。

实际截图：[官方 MoveIt 界面](https://docs.openarm.dev/assets/images/moveit_v1.0-b227bd3761da26def283564b8922bb20.png)。

官方 WebXR 采集流程另外提供本地网页，展示采集状态、录制、成功/失败标记、暂停/启动等；它是数据采集界面，不是本项目要求的独立桌面关节调试器。可在未来动作录制页借鉴采集状态及结果标记。

来源：[OpenArm WebXR 数据采集](https://docs.openarm.dev/tutorial/data-collection-webxr/)。

## 针对SLAI的设计建议

以下为本项目提案，不是对上述品牌已实现功能的额外声明。

| 页面 | 主要内容 | 当前阶段权限 |
|---|---|---|
| 设备总览 | USB2CAN连接、四轴新鲜反馈、使能与故障摘要、J5禁发送标识 | 只读连接和断开 |
| 关节监视 | 每轴实际软件角度、编码器角度、速度、温度、模式与超时；清晰单位 | 已有功能换布局，不增加输出 |
| 软件标定 | 查看人工零位、方向、记录来源和日期 | 修改仅针对本地配置；电机设零与参数写入不混用 |
| 模型与仿真 | 自有模型、坐标系、实际与目标姿态、单独仿真模式 | 未接入的3D或IK明确标示待实现，不伪造实时模型 |
| 轨迹和控制 | 单轴点动、轨迹预览、速度与输出限制、执行状态 | 在完成控制后端和验收前禁用；不能只做按钮就开放 |
| 曲线与日志 | 角度/速度/反馈力矩曲线、原始CAN、导出日志、故障时间线 | 可先只读；反馈力矩标明非独立实测 |

建议主布局为固定设备状态栏、左侧页面导航、中央模型/关节主内容、右侧选中关节详情、底部可折叠日志。大段安全提示和路径不应占满主页面；关键警示要短而明确，详细说明放帮助或日志。J5以“已接线但不发送”呈现，不出现能点击的控制入口。

## 实施建议与不复制项

- 推荐后续桌面框架为 PySide6，但属于技术选型建议，当前 Tk 只读程序不因调研而改动。
- 连接状态、通信通道、控制模式、执行状态是不同概念，不能都用一个“已连接”绿灯代替。
- 只读启动为默认状态。实机、仿真、界面演示数据必须明确区分；模拟值不能伪装成电机反馈。
- 编码器角度和软件角度要并存但主次分明；目标与实际不能共用一个可编辑数值框。
- 不复制 Seeed 的硬件写中位或松灵的 All Set Zero/Random/Reset 等动作到首页。用户已明确目前不改电机参数。
- 软件“停止/失能”不能标称成经过安全认证的硬件急停。实际允许的指令必须由后端白名单和状态机约束，不能仅依赖按钮灰色。
- 主窗口和后台通信应分离，界面卡顿不应决定控制循环；这需要另行实现和验证，不是皮肤改造即可完成。

## 调研限制

这是截至核查日的官方文档和公开仓库参考，不是对全部产品版本和闭源软件的完整审核。未把社区二次上位机或销售站宣传当作官方功能依据，未尝试运行品牌控制程序连接SLAI硬件。正式复制源码前还需分别审查许可证、依赖和协议兼容性。
