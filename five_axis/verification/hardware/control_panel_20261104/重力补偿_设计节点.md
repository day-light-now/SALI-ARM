## 2. 现有机械臂的实测数值（暂定质量）

基础系默认 `+Y` 向下 9.80665 m/s²（文档默认，现场未确认）；J3 固定安装偏置 `+π`（沿用现有 MuJoCo 模型）。硬件的 `hardware_sign`：J1/J2/J3 = +1、J4 = −1，`τ_motor = sign·τ_urdf`。

| 姿态 | τ_urdf (J1..J4) N·m | 门禁余量 |
|---|---|---|
| 实机起点 [-4.109, 0.109, 1.596, 0.809]° | −0.139 / 0.016 / 0.001 / 0.018 | 很大 |
| 实机 +10° 点 [5.891, 10.109, 11.596, 10.809]° | 0.748 / 0.917 / −0.020 / 0.138 | 大 |
| 工作空间最坏 | J1 5.042、J2 4.788、J3 0.390、J4 0.384 | 63% / 48% / 20% / 19% of 8/10/2/2 |

结论：**重力前馈本身在现有估计门禁内**（最坏姿态仍有余量；2.4k 网格无一超门禁）。但门禁是 `kp·位置误差 + kd·速度 + τ_ff` 的合力，真正的瓶颈在 J3/J4 的 2 N·m：

- 静止时 J3/J4 的余量约 1.6 N·m（≈0.58° 误差）；
- **0.25 rad/s 扫描时，`kd·v = 5×0.25 = 1.25 N·m` 已占 J3/J4 门禁的 62%**，再加 τ_ff 与位置误差，J3/J4 只剩约 0.13° 误差余量；
- 因此摩擦扫描（0.05/0.12/0.25）与重力前馈叠加时，J3/J4 可能触到 `OBSERVED_STATE_REQUEST_GUARD_NOT_HARD_CLAMP` 而全停——这是保护阈值问题，不能靠面板绕过。

## 3. 三个必须先定的条件

1. **质量/重心标定**：现有质量是 CAD 暂定（轴承、打印填充率、电机转子/定子分配、末端负载均未实测）。用于实机前馈前需要称重/重心标定，形成新的质量档案；否则只能算“估算展示”，不能算补偿。可先用现有档案做方向和量级验证（小角度、单轴、有支撑）。
2. **驱动 τ_ff 通路**：需要 `native_command()` 增加 `tau` 参数并在 `controls()` 里填 `sign·τ_urdf`；同 `estimate_guard` 的合力关系必须一并评审。这是 `src/slaihand_hardware/` 受保护文件，需 Codex 实现或授权（与调参接口同一个决策点，可合并成一条“增益 + 前馈”接口）。
3. **恒速摩擦扫描入口**：现有 JTC 五次插值不能保持恒速；面板最多 12 个路点。要做 0.05/0.12/0.25 rad/s 的单轴上下扫描，需要一个新的**有界恒速实验客户端**（固定 argv、隔离域、单轴、限位内、速度≤0.25、可随时停止、自动失能），或改用“多小段近似恒速 + 离线拟合”的保守做法。真实动作由用户执行。

## 4. 已交付代码（离线）

- `gravity_ff.py`：四轴重力前馈模型，读取现有 URDF + 现有质量档案 + `hardware_mapping.yaml` 的 `hardware_sign`；输出 `tau_urdf`、`tau_motor`、势能与门禁余量；超限拒绝不裁剪；未加 `--allow-provisional` 拒绝运行；不写任何 ROS/CAN/Flash。

- 数值探针 `gravity_probe.py`（本轮一次性分析脚本）。

## 5. 建议顺序

1. Codex 确认“增益 + 前馈”接口（topic 或 srv）与驱动侧归属；
2. 用户提供称重/重心（或先用现有档案做小角度方向验证）；
3. 实现恒速单轴扫描客户端，先做 **J1/J2**（门禁余量大），J3/J4 先用 0.05/0.12；
4. 用 `effort_estimate`、位置、速度拟合库仑+粘滞摩擦；
5. 先只做“重力前馈 + 显示”，摩擦补偿作为第二档；
6. 全程 Codex 验收后再用于实机；PTY 理想跟随不能验证真实重力/摩擦效果。
