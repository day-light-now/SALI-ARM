# 模型补偿计划转换器（离线，2026-11-10）

把已拟合的静态重力下垂模型（`sag_model_20261110.json`）变成**任意计划可用的
位置前馈补偿**：`command = desired − predicted_sag`。不启动驱动、不碰硬件。

## 用法

```bash
# WSL / Linux
python3 compensate_plan.py plans/V1sub_sag_20261110.json V1sub_modelcomp
```

Windows 离线入口：把计划 JSON 拖到 **`make_comp_plan.cmd`** 上即可；只调用 WSL
里的转换器，不会启动驱动或运动。

输出：
- `plans/<name>_20261110.json`：补偿后的计划（首末仍为绝对零，move/dwell 不变）；
- `comp_plan_<name>_20261110.json`：逐点 desired / predicted sag / compensated 报告；
- 拒绝时只打印原因，不写计划。

## 安全保护（强制）

1. **训练域检查**：每个路点必须落在 T1a/T1b 训练姿态范围 ±2° 内；
2. **外推检查**：预测补偿量不得超过训练下垂包络（当前上限 3°）；
3. **端点**：第一个/最后一个路点保持绝对零；
4. **限位**：逐点检查五轴 URDF 限位；
5. **时间**：move_s/dwell_s 和总时长保持不变。

因此 `T2_sag`/`T2r_sag`（预测补偿 6.24°，大角度混合姿态）和 `V2_sag`（5.86°）
会被拒绝；`JZ` 因 J5 到 ±20/25° 超出训练域（-17…17°）也会被拒绝。这是有意的：
模型只对已验证姿态附近负责。

## 离线精度（用已有测量数据回算）

| 指标 | 数值 |
|---|---:|
| 未补偿基线 V1 下垂（总体 RMS / max） | **0.484° / 1.531°** |
| 模型预测下垂 vs 实测下垂的误差（V1，11 个窗口） | **0.230° / 0.525°** |
| 模型补偿后 V1subc 实测残差（8 个内部窗口） | **0.205° / 0.443°** |
| 逐点迭代补偿（JZ iter2，测量后修正） | **0.0775° / 0.164°** |

解读（残差口径：实测 − **原始目标**，不是实测 − 补偿指令）：
- 模型补偿是**一次到位的粗补偿**：V1 类姿态预期残差 ~0.23°，V1sub 子姿态实测 0.205°；
- 逐点迭代补偿仍更准（0.0775°），但需要每点测量；
- 需要高精度时仍建议“模型粗补偿 + 逐点测量迭代”；
- 两种方式都只是**位置前馈**，不是转矩 FF，也不影响 FF/自由拖拽的准入限制。

## 方向迟滞补偿（2026-11-11 新增，离线验证）

真机 H2/H4 显示同姿态不同接近方向有明显残差差（H2 spread J1 0.787°/J2 0.380°，
H4 J1 0.677°/J2 0.274°）。用 H2/H4 同姿态对拟合常数方向偏置：

- `hysteresis_model_20261111.json`：`delta_deg = [-0.365, -0.163, 0, 0, 0]`
  （J1/J2；J3–J5 近 0）；
- `compensate_plan.py --hysteresis`：按计划序列推断接近方向，命令减去
  `delta*sign`，首末零端点不补偿；仍需通过域/限位检查；
- 交叉验证（H4 拟合→H2 应用）同姿态 spread：H2 J1 0.787°→0.113°、
  H4 J1 0.677°→0.116°；用两数据平均拟合 → ~0.06°；
- 这是**位置前馈**的方向偏差补偿，不是转矩 FF；已准备 `J1H_m8/0/p8` 三条
  真机验证计划（`j1_hysteresis_plans_20261111.json`），硬件验证前默认不启用。
