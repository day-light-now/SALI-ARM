## 2. 配对结果（离线提取，`gc_windows_20261109.json`）

每计划在 +10° 目标处有两次正/反接近配对。方向半差≈一阶静摩擦；配对均值用于
抵消它。同会话两次重复的差反映重复性。

| 计划 | 运动轴 | 半差 1 / 2（重复差） | 配对均值 1 / 2（重复差） | 实际 q up / down |
|---|---|---|---|---|
| GC09 | J1 | +1.102 / +1.089（−0.013） | +2.222 / +2.210（−0.012） | 8.918 / 9.595° |
| GC10 | J4 | +0.873 / +0.872（−0.000） | +1.051 / +1.052（+0.001） | 9.429 / 9.989° |
| GC11 | J2 | +0.643 / +0.641（−0.002） | +2.352 / +2.350（−0.002） | 9.069 / 9.442° |
| GC12 | J3 | +0.838 / +0.839（+0.001） | −0.079 / −0.080（−0.001） | 9.682 / 10.273° |

单位 Nm；上游其它轴在配对间的 effort 半差均 ≤0.01 Nm（见 JSON）。

要点：

- **同会话重复性非常好**：半差与配对均值的重复差 ≤0.013 Nm。
- **会话间有漂移**：GC11 第一次尝试（同一计划、故障前）得到半差 +0.663、
  配对均值 +2.506；重采为 +0.643 / +2.352 —— 配对均值 **差 0.15 Nm**。
  这不是同会话重复性误差，可能是时间/驱动会话/温度/静摩擦状态差异；
  模型拟合应把“会话”作为干扰项或至少报告该量级。上一次 GC11 尝试的配对
  窗口完整（仅缺最终零），保留在 `raw/gc11_aborted_20261109.jsonl.gz`。
- J1/J2 的配对均值 ~2.2–2.4 Nm、J4 ~1.05 Nm、J3 ~−0.08 Nm（J3 轴近竖直，
  重力矩小，与预期一致）。这些是“重力+残余偏置”的候选量，仍需复拟合判断。
- 方向半差 0.64–1.10 Nm 与既有 J5 结论同量级；单方向数据不能直接拟合重力。

## 4. GC12 第一次尝试：driver 崩溃（严重，根因未定）

时间线（本地时）：

1. 15:36 重启驱动（新 audit `waNPuU.jsonl`，`J5_QUALIFIED`）。
2. 15:38:33 启动 GC12；驱动按 ARM 请求 ramp，STAGE 到
   `RAMP_COMPLETE_NOT_POSITION_ACCURACY_ACCEPTANCE`（state 5，steady_s 12673.17）。
3. 约 1.5 s 后（steady_s 12674.694，cycle 10541）驱动写出该周期 MIT 帧后
   **进程消失**；审计在该周期中途截断，无 STAGE/异常记录；launch 也消失，
   仅剩 robot_state_publisher。
4. 客户端等待超时，记录“等待超时…”、`stop_result=已请求停止，未确认新失能`；
   `last_observed_status` 显示五轴 `motor_state=1, control_state=5, hold_ready=1`
   （**仍使能**）。
5. 只读回验确认五轴非失能（PREFLIGHT_FAILED nonzero=J1..J5），驱动已死无法发
   停止 → 按协议请操作者**物理切电**。切电后只读回验：适配器在，但所有轴无
   反馈（已失能/断电）。证据：
   `evidence/j5_timeout_safetycheck_20261109.json`（切电前，五轴使能）、
   `evidence/j5_timeout_safetycheck_after_cut_20261109.json`（切电后，无响应）。
6. 操作者恢复供电后：J5 TIMEOUT 已回 0（RAM 参数，预期）→ 写一次 0→2000、
   取新证据、重建 artifact → 重启驱动（本脚本设 `ulimit -c unlimited`、
   `RCUTILS_LOGGING_BUFFERED_STREAM=0`）→ 重采 GC12 **成功**（exit 0，9/9 判据通过）。

已知事实与限制：

- 崩溃发生在“只使能、未开始轨迹”阶段；无轨迹运动，机械臂由支撑保持。
- 崩溃时日志因此前 `RCUTILS_LOGGING_BUFFERED_STREAM=1` 缓冲而丢失；
  WSL `core_pattern` 为 `|/wsl-capture-crash`，未找到本地 core 文件。
- 崩溃前最后记录是 MIT 帧写出（cycle 10541）之后；无异常文本。
- **重采未复现崩溃**；本次与崩溃时的差异：重新上电、干净单驱动会话、
  无缓冲日志、core 已启用。因此根因仍未知（候选：控制循环未捕获 C++ 异常、
  串口/审计 worker 路径、WSL/USB 主机层）。**不得**据此宣称已修复。
- 此前还发现一次**意外重复 launch**（两次调用启动脚本）；驱动串口使用
  `flock(LOCK_EX)+TIOCEXCL`，重复实例无法占用串口，硬件只注册一次；
  已清理。GC11 的串口故障按真实 USB 链路问题记录。
