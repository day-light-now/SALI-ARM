## A. 暂定负载声明（position-only identity source）

文件：`src/slaihand_bringup/config/load_3p5kg_provisional.yaml`

| 字段 | 值 | 说明 |
|---|---|---|
| `schema` | `slaihand_load_declaration/1` | 声明 schema |
| `load_id` | `j5_3p5kg_provisional` | 新五轴负载候选标识 |
| `mass_kg` | `3.5` | **用户估计值**（2026-11-08 对话），非测量 |
| `mass_source` | `user_estimate_only_not_measured` | 明确未测量 |
| `geometry_status` / `com_status` / `mount_status` | `unknown` | 几何/质心/安装未测量 |
| `gravity_status` | `PROVISIONAL` | 暂定 |
| `formal_gravity_allowed` | `false` | 禁止正式重力 |
| `gravity_fit_allowed` | `false` | 禁止用本档案做重力拟合 |
| `gravity_ff_alpha` | `0.0` | 禁止重力前馈 |
| `float_enabled` | `false` | 禁止 float |
| `do_not_reuse_load_id` | `no_end_load` | 明确**不重用**旧四轴无负载档案 |
| `measurements` | `[]` | 没有任何"测量"被写进来 |

纯 helper：`src/slaihand_bringup/scripts/load_declaration.py`

- `load_declaration(path)`：读文件、校验上面全部约束、返回
  `sha256 = 实际文件字节 SHA256`（不是重新序列化后的 hash）。
- 拒绝：`no_end_load`（`LOAD_ID_STALE`）、伪造测量/几何/质心数值、
  `formal_gravity_allowed=true`、`float_enabled=true`、`gravity_ff_alpha!=0`、
  schema 错误、文件缺失。

### 候选启动如何使用它

新文件：`src/slaihand_bringup/launch/slaihand_canusb_five_axis_candidate.launch.py`

- `mass_profile_sha256` = 声明文件**实际 SHA256**（文件变化即身份变化）；
  `load_id` = 声明文件里的 `load_id`。
- `mass_profile_sha256` 参数省略（默认）→ 自动使用文件实际 SHA256；
  显式传空值 → 拒绝（仅 `test_only_mass_profile:=true` 的测试路径允许）；
  显式非空但与文件实际 SHA256 不一致 → 拒绝（`MASS_PROFILE_HASH_MISMATCH`），
  除非显式 `test_only_mass_profile:=true`（只允许出现在测试路径）。
- 每次启动都检查 `gravity_ff_alpha == 0` 且 `gravity_float_enabled == false`，
  并检查声明本身 `formal_gravity_allowed/gravity_fit_allowed/float_enabled`
  全为 false；否则拒绝启动。
- 不传 `j5_artifact` 时：以 **unqualified / feedback-only** 启动
  （`j5_qualified=false`，生产默认），只带负载身份，不开启 J5 运动。
- J5 sign/zero/limits **只**来自 `hardware_mapping.yaml`；`j5_hardware_sign`、
  `j5_zero_offset_rad`、`j5_limit_lower/upper` 参数只用于拒绝手工覆盖。
- `canusb_five_axis_motion_policy.yaml` 未改动；其 `load_id:
  new_load_3p5kg_j5_provisional` 仅作为旧 launch 的 fallback。候选启动以声明
  文件为权威，传声明里的 `load_id`。

旧路径兼容：`slaihand_canusb_five_axis_motion.launch.py` 只新增了一个默认空
的 `load_id` 参数（空 → 继续用 policy 的 load_id），现有测试 launch 行为不变。

## B. J5 运动校准 artifact / 准入

纯脚本：`src/slaihand_bringup/scripts/j5_motion_artifact.py`（无 ROS、无硬件访问）

### 生成条件（必须先满足，否则拒绝生成）

1. timeout 证据文件存在且满足工具契约
   `verification/hardware/five_axis_20261107/evidence/j5_timeout_setup_evidence.json`
   （`schema: slaihand_j5_timeout_setup/1`）：
   - `ok is true`、`exit_code == 0`、`error is null`、`write_outcome == "complete"`、
     `write_attempts == 1`、`parameter_writes == 1`、`write_data_hex` 为 RID9/2000 帧
     `05 00 55 09 d0 07 00 00`；
   - `timeout_before == 0`、`timeout_after == 2000`、
     `readback.matched is true` 且 `readback.observed == expected == 2000`；
   - `all_motor_state_zero is true`（若带 `axes`：J1..J5 全部 `motor_state==0`、
     `valid==true`、`feedback_age` 在 0..0.25 s）；
   - `j5_id == 5`、`master_id == 0`、`control_mode == 1`、
     `profile = {pmax_rad: 12.5, vmax_rad_s: 10.0, tmax_nm: 28.0}`（与 mapping 一致），
     `device`/`port_argument` 为实际 `/dev/...` 端口；
   - `flash_written`/`enabled`/`mit_sent`/`motor_zero_written` 全部 false；
   - `session_id`、`host_boot_id`、非未来方向的 `observed_at`（UTC）存在，
     且证据在 `--max-evidence-age-s`（默认 1800 s = 30 min）内；
   - `tool.sha256` 为 64-hex、`audit_path` 存在。
2. `hardware_mapping.yaml` 里 J5 `commissioning_timeout_count` 已由 Codex 在真实验证后
   回写为 `2000`。**如果 source 仍是 0，生成直接拒绝 `TIMEOUT_SOURCE_ZERO`**：
   TIMEOUT0 期间不可能存在合法 artifact，也不接受占位/合成证据。
3. mapping/model/policy/load 声明四个文件都存在且与内容一致。

### Artifact 文件

顶层：`{"schema": "slaihand_j5_motion_calibration/1", "payload": {...}, "sha256": "<canonical payload SHA256>"}`

`payload` 绑定：`qualification="j5_motion"`、`joint`、`generated_at`、`boot_id`
（= timeout 证据的 `host_boot_id`，证明证据来自哪次主机启动，**不是**驱动程序
`boot_id`）、`session_id`、`device`/`port_argument`、`load_id`，以及
`hashes = {mapping_sha256, model_sha256, policy_sha256, load_declaration_sha256,
timeout_evidence_sha256}`；`j5 = {can_id, master_id, hardware_sign,
zero_offset_rad, limits_rad, control_mode, profile}` 全部来自 mapping；
`timeout = {timeout_before, timeout_after, readback, all_motor_state_zero,
write_outcome, observed_at}`；`load/policy` 段只记录暂定/position-only 状态。
`sha256` = 对 payload 做 `json.dumps(sort_keys=True, separators=(",",":"))` 后的 SHA256。
任意 64-hex 无法通过重算校验。

### 准入校验（`validate_artifact` / 候选 launch）

- 重算 canonical payload SHA256 必须与文件 `sha256` 一致（篡改/任意 64hex → 拒绝）。
- schema、qualification、joint、boot_id、device 格式。
- mapping/model/policy/load 四个文件**当前** SHA256 必须与 payload 记录一致
  （任一份文件变化 → 对应 `*_HASH_MISMATCH`）。
- J5 sign/zero/limits/can_id/control_mode/profile 必须与当前 mapping 完全一致
  （`J5_*_MISMATCH`）；mapping J5 TIMEOUT 必须非 0 且等于 artifact 的
  `timeout_after`。
- timeout 证据 SHA 必须匹配（传入 `--evidence`/launch `timeout_evidence` 时重算）；
  `timeout_after >= 2000`、`readback == 2000`、`all_motor_state_zero is true`、
  `write_outcome == "complete"`；TIMEOUT0/缺失 → 拒绝。
- 声明必须是 PROVISIONAL，且 `formal_gravity_allowed/gravity_fit_allowed/float_enabled`
  全 false、`gravity_ff_alpha == 0`；policy 同样必须 alpha 0 / float false。
  任何把暂定负载升级成正式重力/前馈的篡改 → 拒绝。
- 默认 30 min 年龄限制（`--max-age-s` / launch `max_artifact_age_s`），过期拒绝
  （`ARTIFACT_STALE`）；未来时间也拒绝。
- `expected_device` 给定时必须等于 artifact 的 `device` 或 `port_argument`
  （`DEVICE_MISMATCH`）。

候选 launch 只有在校验通过后才把 `j5_qualified:=true` 和
`j5_calibration_sha256=<artifact payload SHA256>` 传给现有驱动 launch；
J5 sign/zero/limits 从 mapping 传；任何裸 `j5_qualified`、裸
`j5_calibration_sha256`、手工 sign/zero/limits 参数都会被拒绝（无任意 hex 入口）。

## Codex 在 timeout 工具成功之后的准确命令

  --model "$D/urdf/slaihand_five_axis.urdf" \

  timeout_evidence:=verification/hardware/five_axis_20261107/evidence/j5_timeout_setup_evidence.json

### 首次 J5 运动的受保护客户端命令（Codex 仅在准入通过后执行）

计划文件：`verification/hardware/five_axis_20261107/j5_first_motion_10deg.json`
（J5 相对 +10°，J1–J4 相对 0°，2 s/段；不启用重力/FF）。

```bash
cd /mnt/d/CodexData/Projects/机械臂/slaihand_five_axis_ws
source /home/xuyu/.cache/dsh_five/install/setup.bash

python3 src/slaihand_bringup/scripts/commission_supported_trial.py \
  --plan verification/hardware/five_axis_20261107/j5_first_motion_10deg.json \
  --joint-count 5 --j5-limits-deg -90 90 \
  --execute --ack-supported --ack-clearance --ack-native-output \
  --hold-seconds 1 --output-directory /tmp/j5_first_motion
```

**重要：标准 arm 不是 J5-only。** 客户端调 `arm_supported_current_pose`，
驱动会依次使能全部五个 active 轴（J1–J5）再 ramp；J1–J4 也被使能，只是保持
当前相对 0°。不要写成“只使能 J5”。执行前保持 STOP/切电可用，反馈门限、
50 ms gap、5 ms 写 deadline、3 次 EAGAIN 退出、60 ms 停止反馈均未改动。
首次只做这一条 +10°→返回当前位；禁止加载旧静态重力轨迹，禁止 gravity/FF。

不带 artifact 的 feedback-only 候选启动（不需要 TIMEOUT 证据，适合先确认驱动/页面身份）：

```bash
ros2 launch slaihand_bringup slaihand_canusb_five_axis_candidate.launch.py \
  port:=/dev/ttyUSB0
# 期望 runtime_identity: load_id=j5_3p5kg_provisional,
# mass_profile_sha256=<声明文件实际 SHA256>, j5_motion_qualified=false
```

> 注意：artifact 默认 30 min 过期；每次真实运动会话前重新执行第 4/5 步。
> 不要手工填写/复制 64-hex；候选 launch 不接受裸 J5 hash。
