## 补偿对比方式

同一文件可用于baseline和后续FF候选对比，保持轨迹SHA、绝对起点、增益策略、载荷、方向和停留时间一致。记录当前编码Kp、输出状态、实际姿态、有符号误差、速度、effort估算、故障/停止及温度；effort仍不是实测电流。

采样按计划arrival/end对齐，在dwell内部取静态窗口并检查整个窗口参考跨度和实际速度，不使用“相邻参考变化很小”的旧分组方法。正反接近同一目标应分别保存，再计算配对均值与半差，不把两条混为独立随机样本。

当前 `identification_codex_20261109/offline_ff_candidate.json` 尚未通过独立精度筛选。本次交付的是**新的运动参考轨迹**，没有为它开启FF或修改driver；轨迹文件本身也不会启用前馈。生产模型、补偿限幅/变化率及异常退出须另行具备有效验证。

## 入口与终点

- 候选入口假定新鲜反馈的五轴绝对角均在±2°内。首段8秒只用于小范围对零；若起点更远，应按真实起点重新预览和规划，不能把旧C session结束时的位置当作当前反馈。
- 必须使用普通五轴轨迹JSON入口，保留 `absolute_deg`。现有 `five_axis_trajectory_groups.py` 仅接受相对坐标，**不要把这些文件改成relative后塞进旧组**。
- 关节路点已按canonical J1–J4限位和已记录J5 ±90°校准范围检查；这不是网格碰撞/线缆净空检查，也不证明所有组合姿态已实机通过。
- 最终目标精确为五轴0，但实际完成要以最终新鲜反馈窗口为准：例如每轴末尾最大绝对误差≤0.5°、窗口采样跨度足够、无STOP/UNKNOWN。JTC成功或JSON写0都不能单独证明实际回零。
- 异常停止时保留现有STOP/UNKNOWN处理，不为强行回零继续运动；用户要求的“终点是0”已落实为每条正常轨迹的最终参考点。
