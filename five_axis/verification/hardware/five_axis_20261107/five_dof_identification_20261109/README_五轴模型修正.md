# 随 J5 输出转动的3.5 kg盒体：五轴模型修正

2026-11-09，输入版本 `5cebc3f`。本次只读取本地原始记录/审计，未启动设备或应用FF。

**五轴重力计算结构已修正：电机本体保留在J4/link4，盒体置于随J5转动的下游。得到物理圆周约束的候选模型，但独立验证与几何稳定性仍不足，没有选定可部署参数。**

## 新旧假设的区别

原30点采集和GC01–GC04都基本固定J5，旧候选可用link4中的一个固定等效质心描述当时的盒体姿态。这不等于盒体在所有J5角度都固定在link4。

本次记录明确：**3.5kg不含电机本体，盒体确实随J5输出转动**。因此旧 `[110,9,−47] mm` 只能保留为固定J5姿态下的条件候选，不能直接作为全五轴通用质心。

继续沿用用户确认未变化的安装约定：基座重力 `[0,+9.80665,0]m/s²`，J3固定放置偏置π，canonical J1–J4 URDF几何；既有J4340电机质量不重复添加。

现有URDF中的J5原点为identity、轴为+Z，但源文件明确说这是占位，不是实测安装几何。本次没有把占位J5坐标当真，也没有偷偷改URDF。

## 五轴能量模型

在link4坐标中表示盒体质心轨迹：

```text
r4(q5) = b + u cos(q5) + v sin(q5)
U(q) = U_old(q1..q4) − m g·p4(q1..q4)
       − g·R4(q1..q4) [h_b + h_u cos(q5) + h_v sin(q5)]
τ_i = ∂U/∂q_i, i=1..5
h_b=m b, h_u=m u, h_v=m v, m=3.5 kg
```

同一个势能函数生成J1–J5保持力矩，包含J5转动引起的上游力矩变化，避免只给J5叠加一个与上游不一致的角度多项式。

真实单轴刚体转动还必须满足 `u·v=0`、`|u|=|v|`。先做线性自由拟合，再做显式刚体约束的非线性拟合；刚体版本采用18组初值，未硬编码假设的J5安装轴。

## 重要数据现象：0°的来向依赖

新J5序列：

| 目标J5 / ° | 实际J5均值 / ° | effort估算均值 / Nm |
|---:|---:|---:|
| 起点0 | +0.284 | −0.877 |
| +10 | +9.748 | +0.612 |
| −10 | −9.683 | −0.988 |
| +20 | +19.649 | +0.896 |
| −20 | −19.693 | −0.951 |
| 终点0 | −0.284 | +0.727 |

所有6个窗口均通过原客户端0.5°判据。但两个0目标的力矩估算差为1.604Nm，半差0.802Nm，均值−0.075Nm。实际姿态不是完全相同，因此0.802Nm只能称为**路径依赖的量级**，不能直接宣布测得了库仑摩擦系数，更不能把±0.8Nm全部称为重力。

辨识中增加“接近方向干扰项”仅用于分离这种影响；它不是重力项，也没有作为控制补偿输出。其他贡献可能包括静摩擦、间隙/弹性、支撑和估算偏置，当前不能唯一判因。

## 模型结果与拒绝采用的原因

自由9参数势能回归器数值秩为9，但条件数约940。纯重力拟合给出 `|u|≈1.984m`、`|v|≈0.068m`，夹角余弦0.783，明显不满足刚体圆周约束。因此这种“可拟合”结果不能升级为真实盒体质心或空间J5轴。

刚体约束候选：

| 假设 | q5=0时COM相对link4 / mm | J5±20°保留误差RMSE / Nm | 上游保留误差RMSE / Nm |
|---|---|---:|---:|
| 纯重力 | `[105.4,8.5,−32.3]` | 0.234 | 1.697 |
| 重力+J5方向干扰 | `[105.4,8.4,−32.6]` | 0.154 | 1.697 |
| 重力+各轴方向干扰 | `[67.7,5.3,−45.5]` | 0.146 | 1.476 |

**表中误差在有干扰项时评估的是“重力+干扰”的总力矩，不是纯重力FF的精度，也不是补偿后的实机位置误差。** J5验证只有±20°两个窗口，J1–J4接近零，不能证明在其他上游姿态也适用。

仅把J5方向项加入模型，拟合轴方向就从约 `[0.391,0.920,−0.034]` 变为 `[0.999,−0.005,0.045]`，相差约67.4°。加入各轴方向项，COM的x又变化约38mm。说明“选哪个轴/质心”很依赖干扰假设，不能依据最低训练误差选择为实测几何。

因此此次交付的是**经过验证的五坐标能量模型计算结构与未选用的候选族**，不是已完成空间标定的五轴控制器。`five_dof_offline_candidates.json` 中 `selected_for_deployment=null`、`deployable=false`；没有创建冒充正式质量profile的文件。

## 接下来最能解决问题的信息

1. J5轴线在link4中的实际方向和轴上一点。已有CAD中若有该电机的可靠安装变换/轴线，优先从那里取，避免重新确认基座安装方向；此处缺的是新增输出关节的具体几何。
2. 在相同上游姿态下，同一J5目标由两边分别接近的成对保持，覆盖至少数个目标。当前只有起止0目标构成近似反向配对，±10/±20分别与来向绑定，重力和摩擦容易混淆。
3. J5在至少两个不同的J1–J4绝对姿态下转动的数据。现有J5激励几乎只改变q5，不能独立验证重力方向改变后的耦合预测。

这些是后续数据设计建议，本次没有自动生成并执行新硬件动作。质量准确称重及每轴力矩/电流标定仍有价值。更多相同上游姿态的单方向J5点，不能替代空间几何与反向配对。
