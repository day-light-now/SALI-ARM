# SLAI 四轴实机控制规格与验收表

版本：2026-10-31，保护与影子阶段。该规格取代“先让固定某一轴小幅运动”的临时安排。

**本轮实现：统一命令数据结构、MIT/PV 影子编码、参数快照、100 Hz 目标主机影子记录、全局诊断锁存。真实运动网关继续关闭。没有修改电机参数或发送运动帧。**

## 1. 当前证据与边界

用户提供的当次自检截图：四轴新鲜、正常失能；J1=模式2，J2–J4=模式1；四轴 TIMEOUT=0；J5未查询。截图是该时刻的观察，不能替代以后每次使能前的实时回读。

硬件记录表：J1机械限位问题未解决；J2的CAN编号断电保持验证尚无记录；J3/J4的人工零位和方向已记录、运动包络待验收。J2记录缺失不证明现在ID错误，但不能据一次在线回读证明永久保持或物理身份唯一。

本地参考：`src/openarm_can/src/openarm/damiao_motor/dm_motor_control.cpp` 与 `dm_motor_constants.hpp`。MIT基本ID；PV为基本ID+0x100，两个float分别为位置和正速度上限。协议映射PMAX/VMAX/TMAX按实机寄存器回读，不套库默认值。未宣称固件特例已验证。

## 2. 对评审意见的技术校准

| 评审观点 | 采用后的准确规则 |
|---|---|
| 阶段0“参数快照不发帧” | 如果读取实机，仍须发只读查询；不发的是运动/使能/写参数帧。读取本地文件则必须标注缓存来源与时间。 |
| TIMEOUT=0意味着持续推 | 不能依赖CAN看门狗退出；驱动仍可能有其他故障保护，不能据此断言任何状态下都无限保持。运动准入必须拒绝看门狗关闭。 |
| 只开J3看门狗一定更危险 | 不能无条件这样断言。关键是所有**将被使能的轴**有一致且经过验证的失联策略，其余轴有可靠被动支撑。本项目暂不执行只改J3的提议，也不把既有仅J3授权扩大为四轴写权限。 |
| 四轴模式统一 | 统一命令接口与验收流程，保留实际模式；不为形式统一强改J1。PV不具备MIT力矩接口，不能静默忽略非零kp/kd/tau需求。 |
| 影子模式零风险推演 | 仅零运动输出；已有只读查询仍在发送。能检查算时、映射、候选包和异常逻辑，不能证明真实受力、耦合、闭环稳定性、实际总线控制时延或机械安全。 |
| ±2°/.02rad/s/1.4961A是四轴包络 | 仅J1/J2历史**模式4**局部试动证据，且支撑条件有限；不跨模式、姿态、负载、型号继承。J3/J4不据此获得包络。 |
| 一轴故障四轴全停 | 全局撤销全部计划/使能授权、不继续其他轴运动；实际停机动作按已验收策略执行。USB断线时无法保证任何停止帧送达，须依靠驱动保护和被动接住。 |
| 零增益=零力矩 | 错。12位对称力矩字段的零通常量化为非零残余；状态失能与“请求小力矩”是两回事。软件停止不能定义为只发零增益帧。 |

## 3. 状态机与权责

```text
DISCONNECTED → READ_ONLY → SNAPSHOT → SHADOW
                                  ↓ 准入证据全部通过（当前未开放）
                               PREPARED
                                  ↓ 用户明确开始
                    TAKEOVER_AXIS_1 → … → TAKEOVER_AXIS_4
                                  ↓ 分轴确认、总线及负载验证通过
                                 HOLD
                                  ↓ 完整票据通过网关
                                TRACK

任一轴故障/过期/会话变化/模式变化/映射变化/主机超时
  → GLOBAL_LATCH → 撤销全部计划 → 已验收的全局停止流程
  → 人工检查 → 重新快照和准入；不自动清故障、重使能或续跑
```

当前代码仅开放READ_ONLY/SNAPSHOT/SHADOW；`core.CommandGateway` 的R2仍拒绝非仿真运动。新影子编码模块没有串口、USB封包或发送对象。

## 4. 统一命令与模式能力

`JointCommand(pos, vel, kp, kd, tau_ff, speed_limit)`：位置rad、速度rad/s、力矩Nm；均在模型输出轴坐标。

```text
q_model = sign × (q_encoder − zero)
q_encoder_target = zero + sign × q_model_target
v_encoder_target = sign × v_model_target
tau_encoder = sign × tau_model
```

| 模式 | 能力 | 限制 |
|---|---|---|
| MIT=1 | 位置、目标速度、kp/kd、前馈 | PMAX/VMAX/TMAX是协议范围，不是机械安全力矩；零力矩有量化残余。 |
| PV=2 | 位置+正速度上限 | vel不是第二个float的同义词。当前影子编码拒绝非零vel/kp/kd/tau_ff；不能声称输出电流已受限。 |

影子候选目标冻结为**开始时的当前反馈姿态**，不是软件零位；kp/kd/tau_ff均为0，只用于检查数据链，**不叫实际保持**。越界直接拒绝，不静默裁剪成另一条运动。未来轨迹若需要限幅/重规划，必须展示新预览并重新确认。

## 5. 保护先于控制

### 5.1 失联与电源切断

- 默认准入策略为“可靠支撑下验证驱动失联退出输出”；当前所有轴的最终动作和延迟仍未验收，不凭J3出现D状态推定其余轴行为相同。
- 必须确认全臂各段及末端负载在全部失能时由台架/吊带/机械支撑接住，而不是只固定底座或靠人临时托举。
- “保持”依赖电源、通信、驱动和控制器持续工作；不能许诺USB失联后仍可受控保持，更不能许诺断电保持。若需要，需另有制动器/被动配重等设计。
- 若选临时RAM参数：每次上电/重连/模式或固件改变后重新读取并完成受控设置与回读；未保存就不得假定保持。若保存Flash：需单独授权、记录原值、新值、写回确认及断电复验。
- 当前仅有临时J3 TIMEOUT=2000的用户授权，尚未执行；四轴写入与Flash保存都未获本轮授权。此处不通过程序自动修改。

### 5.2 停止分成三类

| 情况 | 要求 |
|---|---|
| 正常结束/用户停止 | 若链路健康且已有验收，连续轨迹减速，进入受限当前位置保持；不是运动中直接跳目标。前馈衰减到0不能被等同于无输出。 |
| 一轴故障但链路可用 | 全局锁存、取消四轴计划；对受控轴执行已批准的支撑下停止/失能动作，逐轴确认。失败转“状态未知”，要求电源切断；不报成功。 |
| USB/主机失效或硬件急停 | 不依赖软件补发；由电机保护、硬件回路和机械接住承担。软件急停按钮不能替代硬件急停。 |

不能为避免掉臂而自动无限重发最后目标；也不能在无支撑时把“全停”草率实现成全部失能。

### 5.3 输出力矩、跟随误差与增益

- MIT总输出含kp×位置误差、kd×速度误差和前馈，**只限制tau_ff不等于限制总力矩**。
- 首轮若采用主机PD+FF、驱动kp=kd=0，仍必须校验编码后实际请求的总力矩与量化残余，不能只校验浮点请求；电流—输出力矩关系要按电机型号和传动定义另验收。
- 若采用驱动内非零kp/kd，需在误差/速度包络内证明最坏输出受限，且核实驱动独立限制；不直接复制仿真参数。
- 每轴需要独立的机械局部范围、速度、总力矩/电流、跟随误差、温度阈值及证据。未知项保持未批准；不从TMAX推导额定安全力矩。

## 6. 首次接管必须细化的顺序（当前不执行）

1. 以当前会话核对物理身份、编号、模式、映射范围、失能状态、看门狗和限制；不沿用昨天截图。
2. 获得足够新鲜反馈后生成一次性票据，绑定四轴配置摘要、初始角度、局部包络、周期、增益/输出限制和停止策略。
3. 预装当前姿态目标及明确的零起始速度；对应固件是否在失能时缓存命令，需先验收。
4. 错峰接管：每轴发送、使能确认、跟踪/输出/全局状态确认后才进入下一轴；不是简单sleep四次。全过程其他轴由机械支撑承担。
5. MIT经批准的0.5–1s输出/增益斜坡需限制总输出；PV没有等价的tau斜坡接口，须另验收内部输出限制及接管瞬态，不能伪装实现。
6. 有一项超时/异常立即全局锁存，不继续后续轴。对已经接管的轴执行已验收停止流程；状态未知不算失能确认。

## 7. 时序、丢帧与影子结果的解释

- 影子主机目标10ms（100Hz），使用monotonic时钟；错过时隙跳过，不追赶成突发发送。主机间隔超过50ms会停止本次候选生成并锁存。
- 四轴用同一轨迹时间，不代表四帧物理同时到达。实际需记录周期ID、各轴接收/发送/反馈确认时间、发送顺序、四帧首尾偏差、p95/p99/最大时延和超期。
- 发送顺序需在台架选择固定/轮换策略并留证；调度或USB批传不能只凭921600波特率推断。
- 当前只读Reader约50ms以上发一个查询，四轴反馈不是100Hz；影子会报告每轴实际更新间隔及超过80ms反馈年龄的周期。350ms仅是影子诊断数据上限，不是运动允许延迟；80ms也仅是待验收的诊断参考阈值。
- 2026-10-31计时修正补充：当前程序统一改用perf_counter（本机QPC，分辨率100ns），避免Python3.12 Windows monotonic的15.625ms粒度。查询仍默认50ms/轴次；显式选择快速只读后目标10ms/轴次，实际更新与影子周期均须重新测量。影子从只读线程缓存取数据，UI显示节流到约50Hz；它们不能充当真实控制ACK时延。
- 没有序列号和请求关联时，不把“TX-RX”直接叫丢帧率，不把查询间隔叫控制RTT。真实四轴控制周期当前明确记NOT_MEASURED。
- 影子参考离开初始反馈超过2°会锁存，**该阈值只用于影子诊断，不批准任何轴的2°物理运动范围**。
- 影子只使用当前只读会话的数据，不增加任何CAN发送。只读Worker仍有查询TX，不能把总串口TX标成0。

## 8. 选轴标准与分阶段验收

单轴候选需填五项实测：可用无干涉局部行程、当前姿态重力矩、末端/下游负载、掉电下垂及支撑后果、可观察性。未知不参与排序；不凭编号认定J3最佳，也不凭印象断言J3一定不合适。J1限位问题未关闭前不扩展范围、不为统一而改模式。

| 阶段 | 内容 | 允许的真实发送 | 当前验收 |
|---|---|---|---|
| 0 | 参数/软件映射/模型限位/已验证物理包络快照 | 仅既有只读查询 | 截图已读；导出原始快照待用户操作 |
| 1 | 失联策略、被动接住、急停/断电、RAM/Flash方案 | 此步不要求运动；改参数须有范围明确的授权 | 待硬件确认 |
| 2 | 影子候选、坐标/模式编码、主机周期和反馈年龄 | 仅既有只读查询；运动TX=0 | 软件与离线测试已提供；实测20秒记录待操作 |
| 3 | 按标准选单轴，批准该轴当前姿态局部包络 | 仅该轴的受限命令；J5排除 | 待阶段1/2及准入通过 |
| 4 | 四轴错峰接管与保持 | 每个将接管轴保护通过后才允许 | 未开放 |
| 5 | 四轴局部同步，测完整控制周期/异常策略 | 已批准的四轴命令 | 未开放 |
| 6 | 逐项扩包络 | 每步另存验收、失败回退 | 未开放 |
| 7 | 重力补偿 | 先验质量/质心、安装方向、输出力矩符号与限制 | 仅仿真 |
| 8 | J5 | 模型/映射/保护通过后另行开放 | 禁查询/使能/控制 |

### 逐项签收表

- [ ] 同一只读会话四轴参数快照和原始CAN日志可追溯。
- [ ] J2编号断电保持及物理身份已按可靠支撑下的流程核验，无重复ID证据。
- [ ] 每个拟使能轴的失联动作/延迟及参数上电行为已验证。
- [ ] 全臂和末端负载在全部失能时可被动接住；急停/断电可操作且回路明确。
- [ ] 影子主机时序、配置变化、故障锁存及反馈年龄记录通过；不冒充实际控制时序。
- [ ] 选轴的五项依据和当前姿态局部包络已批准。
- [ ] 总输出限制、量化校核、跟随误差及PV限制已分模式批准。
- [ ] 单轴试验结束/异常后的实际状态有确认，不能只看“发送成功”。
- [ ] 四轴接管和全局异常流程通过后才允许同步运动。

## 9. 软件入口与审计

设备概览增加“导出当前参数快照”“运行20秒影子记录·不下发”“停止影子记录”。旧窗口不会自动加载新代码，需用户断开只读、退出并重新打开。

影子日志：`tmp/commissioning_shadow/*.jsonl`，首行冻结快照，逐周期记录候选/反馈年龄，末行汇总。文件里的candidate_payload从未送入真实驱动。用户可在不改变电机参数的情况下完成阶段0和2。

未来实际接口审计必须按同一command_id区分 ACCEPTED / SENT / DEVICE_CONFIRMED / COMPLETED / FAILED；USB写入成功不算设备确认，设备确认也不算达到目标。当前没有真实运动接口，不生成虚假的SENT/CONFIRMED状态。
