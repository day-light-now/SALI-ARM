# 自动负载补偿采集首轮交付

用户确认当前J1机械端点−80°～+200°、sign=+1，随后明确将自动采集区间缩为软件−70°～+70°。本轮目标端点−69.5°～+69.5°，每段≤10°、参考峰值≤0.02rad/s。没有改变URDF、机械零位或电机参数。J1原生PD160/5、8Nm反馈状态请求估算检查、2Nm积分FF及0.5Nm/s变化率保持，其他原保护保持。

新增auto_load_acquisition.py：有限双向路线、起点/全局范围、映射哈希、逐点与最终停止状态机，不根据重新使能扩大预算。auto_load_runner.py：单J1原生MIT执行、到位稳定窗口、积分负载偏置、四轴实时观测、停止确认与待核/合格数据分离。auto_load_console.py：独立入口、只读预览、四项条件、显式启动、原子checkpoint及最终归档。J2-J4保持被监测，J5不查询或控制。未配置其他轴扫描范围。

同时保存四轴完整姿态、速度、状态、反馈力矩估计、有效当前控制请求估计、温度和反馈时效；未使能/非当前控制轴的请求估计为None，静态候选标志为false。逐帧数据不冒充静态重力标签；只有选轴稳定窗口产生合格点。采集不是重量测量，数据包含摩擦/线缆/外力，拟合及全臂验证另做，不自动应用。

腕部复用依据：wrist_mapping_lab/run700.py、sensorless700.py和700自动采集使用说明.md。复用有限路线、双向稳定数据、日志与停止确认流程，未借用绳索舵机或张力参数。

测试：原11模块+holding_bias+load_calibration+auto_load_acquisition+auto_load_runner，共172 tests / 58.505s / OK。自动采集生产链路用假串口小范围往返，验证真实解析器、协议编码、双向记录、取消、UNKNOWN不归档、停止后合格点归档；±70°完整路线为离线规划检查，不是实机或完整负载动力学验证。GUI隐藏冒烟：启动按钮默认禁用、四项确认默认未勾选、需只读预览、不构造Reader。

额外修正共享ControlSession.cycle：controller.tick当场进入UNKNOWN/DISABLED后立即返回，不再补发原来这一周期的非活动轴CC查询；新增回归覆盖，172项包含此修正。

实际起点为0°的仅示例路线：约42段、29个双向采样点，最坏预算26.37分钟，实际稳定可提前结束逐点等待。示例不得当真实起点，需从硬件只读预览重新生成计划；预览后起点变动>0.5°、软件零位/sign改变、缺少现场确认或未确认失能均不得启用。首轮J2-J4若无法可靠保持或支撑分担J1载荷，则不能采样。

本轮未打开真实串口、未使能/运动/保存Flash，所有运行均为离线假串口或隐藏UI。用户后续操作：打开“自动负载补偿采集.bat”，先只读预览，核对J1±70°路线；确认现场条件后显式启动，结束发结果JSON。状态UNKNOWN需现场支撑切电检查，不自动重试。
