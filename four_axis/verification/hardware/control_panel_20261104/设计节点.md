## 3. 进程与线程架构

```
浏览器 ──HTTP(127.0.0.1)──> HTTP 线程池 ──读快照/入队──> ROS 线程（唯一 rclpy.spin_once）
                                   │                        │
                                   │                        ├─ 订阅三路状态 → 快照
                                   │                        ├─ stop_all/reset/switch 服务（call_async，不阻塞）
                                   │                        └─ 看门狗：子进程/心跳/停止确认
                                   └── 直接终止子进程（不取 ROS 锁）

执行/保持：固定 argv 子进程（sys.executable + 已安装 commission_supported_trial.py）
  └─ 独立进程组；行读取线程进有界环形缓冲；SIGTERM→(2s)→SIGKILL
```

- HTTP 线程只做：鉴权、入队、读不可变快照；**从不**调用 rclpy，也不等待子进程。ROS 线程循环只有 `spin_once(0.02)` + 非阻塞队列/看门狗，因此执行中的子进程、HTTP 请求都不会阻塞订阅或停止。
- 状态快照在 ROS 线程内构建后整体替换引用，HTTP 侧仅在极短的锁内取引用（不持锁做 I/O）。
- 停止请求由 HTTP 立即受理（202），同时（a）置停止纪元、（b）`SimpleQueue` 通知 ROS 线程调用 `/slaihand/stop_all`、（c）直接对子进程组发 SIGTERM。三者互不依赖，任一线程阻塞都不会丢失停止受理。
- 面板记录 `ros_thread_alive`（自增心跳）与 `stop_delivery_latency`；若 ROS 线程不可用，停止响应显式标注“已受理但 ROS 线程不可用”，不伪造成功。

## 4. 状态、目标与所有权

- 电机状态、驱动保护、会话 45 秒上限：**驱动/后端所有**；面板只读，不写参数、不改限位/增益/门禁。
- 轨迹与会话：**受保护客户端子进程所有**；面板不创建 FollowJointTrajectory 客户端、不直接 arm、不直接发轨迹。
- 预览票根、确认状态、操作记录：**面板进程所有**（内存 + 任务专用归档目录）。
- 目标角度：只显示“用户/动作明确目标”——最近一次操作冻结计划的终点，或当前有效预览的冻结点；无目标时为 null。**不把实际反馈当目标**；实际角度只来自反馈。无反馈一律 null，前端显示“—/失联”，绝不用 0 填充。
- 控制阶段来自 `control_state`：0 未使能 / 1 启动前检查 / 2 预载 / 3 使能中 / 4 增益斜坡 / 5 保持 / 6 轨迹 / 7 停止中 / 8 已失能 / 9 UNKNOWN（锁定）。同时显示 `command_owner`（控制器已接管）、`hold_ready`、`disabled_observed`、`audit_ok`、`timeout_count`、`configuration_conflict`、`motor_state`、`control_mode`。
- 初次接管仍为当前位置：使能只由子进程经由既有 `arm_supported_current_pose` 完成，接管后先保持（`--hold-seconds 1`）再切 JTC；面板不提供“使能后直接去输入目标/零位”的路径。

## 5. 计划与预览票根

1. 前端编辑计划（坐标模式 `absolute_deg` / `relative_start_deg`、每点 J1–J4、move_s、dwell_s，1–12 点）；单点与多点走同一计划结构，不另建单轴链路。
2. `POST /api/preview`：服务端用**实时四轴反馈**作起点、URDF 完整限位作界，调用 `compile_plan`；成功后把计划**冻结为绝对计划**（`absolute_deg`，每点绝对角度 + 原 move_s/dwell_s），再对冻结计划重新 `compile_plan` 以得到将实际执行的绝对目标与时间。
3. 票根 `ticket`（32 字节随机）绑定：冻结计划、源文档规范化 SHA256、预览起点（4×rad）、预览时反馈时刻/`feedback_valid`、创建与过期时间（默认 60 秒，可配）、一次性使用标志。
4. `POST /api/execute` 携带 `ticket + 当前计划文档 + 三项确认`；服务端重新规范化该文档并与票根源哈希比对（编辑即失效），并强制检查：票根存在/未用/未过期、三项确认全为 true、反馈新鲜且四轴 `feedback_valid=1`、`control_state=0` 未使能、起点与预览起点逐轴偏差 ≤0.5°、无进行中操作、上次停止/UNKNOWN 纪元之后已重新观测到 DISARMED、心跳新鲜。任一不满足即拒绝并说明原因，票根随即作废。
5. 时间预算：预览与执行都要求 `hold(1s) + 计划总时长 + 8s ≤ 43s`（与客户端 43 秒判定一致）；执行时子进程再按**实际起点**重算峰值速度与时长，超过即失败并停止。
6. 票根一次性：受理执行的同一临界区内标记已用，之后任何重放/重复提交均拒绝。新预览替换旧票根；编辑后前端立即丢弃旧预览显示。
7. 执行时把冻结计划写入 `<archive>/operations/<opid>/plan.json`，源文档写入 `source.json`，子进程 `--output-directory <archive>/operations/<opid>/client`，结果投影进状态与日志。

## 6. 停止竞态与“迟到使能”

- 停止受理是**无条件**的：不取执行互斥锁、不做确认、不受“单任务”限制；停止后立即进入 `stop_epoch` 并**锁定停止门禁**。
- 迟到使能防护分三层：
  1. 驱动：`stop_all` 置 `stop_request_`，`write()` 中 `arm_request_=false` 后才处理，停止之后的 arm 请求被清除；从停止/UNKNOWN 不能直接使能。
  2. 子进程：只从 `control_state==0` 发起 arm；停止后其自身 finally 再请求一次 stop 并确认新失能。
  3. 面板停止门禁（首轮返工 P1 修正）：`_request_stop()` 在同一临界区置 `stop_locked=True`，`preview/execute/hold` **立刻**返回 409 `STOP_LOCKED`，与缓存中是否仍是 stage 0 无关；`_launch()` 在 Popen 前的同一临界区再次检查门禁与停止纪元，关闭“准备→Popen”窗口；停止路径不等待文件 I/O 或启动锁。
- 门禁解除条件（必须同时满足）：`reset()` 已被受理（记录时间戳 R，且复位只能从已失能发起）；随后收到**因果上更新**的动态反馈 `dynamic_at > R`，且四轴 `control_state==0`、四轴一致、`feedback_valid=1`、位置完整。仅收到 DISARMED（未手动复位）、仅收到 reset 的服务接受回复、或复位前发布的旧快照，都不能解锁；停用/旧缓存亦不能。
- 真 UNKNOWN：停止门禁保持锁定，复位被驱动拒绝；面板不重试、不降级、不冒充“已确认”，需要人工处理或重启进程。
- 停止状态机（对外明确区分）：`not_requested → requested → confirmed | unknown`
  - `requested`：HTTP 已受理。
  - `confirmed`：请求时刻之后收到的新动态反馈里四轴 `disabled_observed=1`。
  - `unknown`：请求后 3 秒内未确认，或观察到 `control_state==9`；提示保持支撑并现场切电，不重试使能。
- 停止记录保留：操作员停止后若操作结束仍未确认新失能，面板不再补发会改写原因的内部 stop，只记录“已有停止请求/UNKNOWN”；仅在没有停止请求时才补发 `stop_all`。
- 关闭/断连/停止三方竞态：三者都只做“请求 stop + 终止子进程 + 记录”，不产生新的 arm/轨迹调用；所有动作均带操作 ID 与停止纪元，晚到的旧请求在受理前比对纪元并拒绝。
- 执行完成自动停：子进程 finally 内 `/slaihand/stop_all` + 新失能观察；若子进程异常退出或未确认（且无停止在途），面板补一次 `stop_all`，并在 `command_owner=1` 时**仅停用**轨迹控制器以释放所有权（绝不激活）。

## 7. 浏览器断连与面板退出

- 页面每 1 秒 `POST /api/heartbeat`（带 token + Origin）。仅在执行/保持进行中强制租约：超过 `--heartbeat-timeout-seconds`（默认 3 秒）未收到心跳 → 终止子进程组、请求 `stop_all`、操作标记 `lease_expired`，状态显示有界停止与确认结果。
- `pagehide` 时用 `fetch(..., {keepalive:true})` 调 `/api/lease/abandon`，可更快触发同一停止路径；失败也不影响 3 秒租约兜底。
- 面板收到 SIGINT/SIGTERM：先停止 HTTP 受理 → 终止在途子进程 → 请求 `stop_all` → 有界等待新失能确认（≤4 秒）→ 写操作记录与最终状态 → 退出。保留驱动自身 45 秒有限会话，不改其上限。
- 心跳只在操作进行中强制；空闲时断连不触发任何 ROS 动作。

## 8. 同源 / token / 请求边界

- 只监听 `127.0.0.1`（拒绝 `--host` 非回环）；启动打印带一次性随机 token 的 URL。
- `GET /` 必须带正确 `?token=`，否则 403（页面本身含 meta token，跨源页面读不到）。
- 所有 `/api/*` 必须带 `X-Panel-Token`；POST 还必须 `Origin` 精确等于 `http://127.0.0.1:<port>`（或 `http://localhost:<port>`），缺失/不符即 403。若存在 `Sec-Fetch-Site` 必须为 `same-origin`/`none`。
- `Host` 只接受 `127.0.0.1:<port>` / `localhost:<port>`（防 DNS rebinding）。
- 请求体 ≤64KB，要求 `Content-Length` 且不允许 `Transfer-Encoding`；非 JSON/非对象拒绝。
- 静态资源路径白名单（`/`、`/index.html`、`/panel.css`、`/panel.js`），不做目录拼接，无路径穿越。
- 响应头：`Cache-Control: no-store`、`X-Content-Type-Options: nosniff`、严格 CSP（`default-src 'none'; script-src 'self'; style-src 'self'; connect-src 'self'; frame-ancestors 'none'`，无内联脚本/外链）。
- 单任务互斥：execute/hold 任一进行中，第二个返回 409；预览在操作进行中返回 409。
- 导入 JSON 只当数据：前端不做任何求值；服务端只按 `compile_plan`/形状校验接受，未知键拒绝。
- 日志/结果显示一律 `textContent`，不用 innerHTML。
- 计划存档写入任务专用目录 `<archive>/plans|operations/`（默认 `~/.ros/slaihand/control_panel`），ID 为服务端生成十六进制并校验，不接受任意路径；不读用户私人文件。
- 子进程固定 argv：`[sys.executable, <已安装>/lib/slaihand_bringup/commission_supported_trial.py, '--plan', <归档内文件>, '--execute', '--ack-supported', '--ack-clearance', '--ack-native-output', '--hold-seconds', '1', '--output-directory', <归档目录>]`，不使用 shell，不接受任意命令/任意写入路径；继承面板的 ROS 环境（隔离域测试时即隔离域）。

## 9. 成功语义（不混淆）

- 预览：`accepted=true, completed=true`（校验完成）；执行/保持/复位/停止：`accepted=true, completed=false`（已受理，随后轮询状态看结果）。
- 动作结果与精度判据分栏：`trajectory_error_code`/`trajectory_error_string` 原样显示；`waypoint_results` 逐点显示采样数、跨度、四轴最大误差、是否通过；`waypoints_observed`、`stop_observations_confirmed` 单独显示。
- 标准 JTC 动作成功 ≠ 精度通过；未通过时不得显示成功。无结果文件时显示“无结果（客户端未执行）”，不推断原因。

## 11. 已知限制（写进交付报告）

- 面板不改变驱动会话上限与任何保护；理想 PTY 不能验证重力、实际精度或瞬态。
- 本轮不引导用户运行候选实机控制；实机操作、支撑与切电条件由用户另行确认。
- 停止服务返回“已请求”，新失能确认来自后续动态反馈；`stop_observations_confirmed` 不是物理切力矩证明。
