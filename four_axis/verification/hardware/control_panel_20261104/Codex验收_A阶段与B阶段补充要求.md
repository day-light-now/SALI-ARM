## 需要修正的证据与表述

1. GravityShadow.alpha 恒为 0，estimate() 的 envelope 使用 abs(alpha*tau_g)，所以 headroom 目前不扣除模型重力。交付所称“余量主要被重力占用”与源码不符。明确区分当前已应用命令余量与假设 alpha>0 的预测余量；若没有新鲜参考，P 项未知，不能把按零误差估出的余量当作真实可用余量。面板与日志都说明基准。
2. test_j3_offset_is_applied_exactly_once 只证明额外配置旋转 pi 会改变计算、2*pi 会回到同一结果；不能证明当前 URDF、实物、仿真之间没有重复修正。需用统一模型的坐标链/FK 对照及独立的姿态例子证明额外 pi 的必要性，不能仅以同一偏置的势能差分或另一份同源实现作为物理证明。在证明前保持“待实物核验”，禁止宣称已校准。
3. session180 工作空间是 Codex 于 11-04 有意部署：客户端 178 秒、驱动 180 秒。当前源码 policy 也是 180。integration_notes 中 session45/current speed05 是旧信息，应区分历史与现状。报告本轮查询 WSL 时未发现运行中的 ros2_control_node，无法检查实际进程 maps；不要凭历史路径声称当前加载库。最终测试需保存实际加载 .so 的绝对路径和哈希，不能只比对磁盘中某个未加载文件的字符串。
4. 用户此前已确认基础系 +Y 向下、J3 实物放置转 180°、无额外末端负载。保留确认来源；这不自动证明软件额外关节 pi 偏置正确，也不证明 CAD 质量/重心可信，不要重复要求同一安装方向确认。

## B 阶段验收边界

继续完成默认 alpha=0 的离线实现与隔离域 PTY 验证；不要同时触碰运行中的实机工作空间。

- 用户明确说过不能按仿真重量估计补偿。当前质量档案 ESTIMATE_ONLY_NOT_FOR_HARDWARE 只能作为未标定假设；不能把改状态标签、非零 alpha 或一个普通 UI 勾选等同于正常硬件使用资格。正常应用必须有可信质量/重心或实测辨识依据；若设计受限方向验证，单独写清模式、来源、适用边界并交用户操作，不能默认开启。

- 门禁按最终编码后的完整 MIT 命令检查；前馈、PD 合成估计、保守包络与驱动反馈估计分别展示。现有 request guard 不是驱动总输出的硬钳位。
