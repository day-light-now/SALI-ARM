## 3. 数学约定与实现要求

### 3.1 控制律：MIT 仍由驱动器执行 PD

在无外部接触、单位和坐标统一的条件下采用：

```text
M(q) q_ddot + C(q,q_dot) q_dot + g(q) + f(q_dot) = tau_joint

tau_g       = gravity(model, q_measured)
tau_ff_req  = alpha * tau_g + beta * tau_friction
tau_joint_est = Kp*(q_des-q_measured)
              + Kd*(v_des-v_measured) + tau_ff_applied
```

`tau_g` 用当前实测姿态计算；第一版不加惯性或科氏前馈。`alpha`、`beta` 分别是重力与摩擦补偿系数，初始为零，重力启用时有斜坡，摩擦默认关闭。它们是明确记录的实验参数，不作为自动掩盖模型错误的调参器。

保留 MIT 模式，由驱动器执行内部 PD；上位机只计算额外前馈及必要的命令估计，不把同一 PD 又加进 `tau_ff`。核查现有控制器是否已发送重力或 effort，避免重复补偿。用 mock 报文证明 `tau_ff=0` 时原控制路径兼容。

### 3.2 坐标和力矩映射

建立唯一坐标转换模块。对固定线性映射写清：

```text
q_model = A*q_protocol + b
v_model = A*v_protocol
tau_protocol = A.T*tau_model
```

力矩变换由虚功一致性得到；它与角度映射中的齿比方向有关。只有协议位置、速度、力矩均已在同一关节输出侧、且 A 仅包含方向符号时，才能简化成 `tau_motor = sign*tau_urdf`。若协议是电机侧，必须查明齿比与力矩常数的定义；效率/损耗另行建模，不能重复乘减速比。

为 J3 单独列一个零点例子，证明 `+π` 未在 URDF origin、反馈映射和算法中重复加入。所有算法接口用 rad、rad/s、N·m、kg、m，界面可显示角度但明确转换。

### 3.3 重力后端

首选与项目兼容的 Pinocchio，使用 `computeGeneralizedGravity(model,data,q)`；同模型下应与 `rnea(model,data,q,0,0)` 一致。按关节名称建立索引，不假定 URDF 文件顺序就是电机顺序。注意 continuous 等关节的 `nq` 和 `nv` 可能不同。

如暂不能在 WSL 安装 Pinocchio，不因此停止整个任务：可将已有 `gravity_ff.py` 整理为生产计算模块，用势能差分和独立后端交叉检查；或选择兼容的 MuJoCo 后端。报告使用哪个后端、版本、未完成的交叉验证。不能仅在 Windows 离线算出几组数，就宣称 WSL 实时补偿已完成。

MuJoCo 的 `qfrc_bias` 包含科氏、离心与重力项。提取重力时，在独立计算 Data 中设置对应姿态、零速度并更新相关计算；不能把运动中的 `qfrc_bias` 直接命名为纯重力。比较时统一基础系、模型质量、固定变换、关节顺序与单位。

校验符号：定义物理向下加速度 `g_base`，势能 `U(q)=-Σ m_i*g_base·p_com_i(q)`，本说明中的 `g(q)=∂U/∂q`，即用于抵消重力的关节力矩。不能再凭直觉对后端结果统一取负号。

### 3.4 模型与负载

基础系重力用显式配置：若 `R_world_base` 将 base 向量转到 world，则 `g_base=R_world_base.T*g_world`。`+Y` 向下只是来信中的待确认假设，不能作为已校准的实机事实。

质量与重心可来自 CAD，不要求所有连杆必须拆下称重后才能写软件。为每项记录来源、单位、坐标系、置信/误差范围和版本；核查总质量与实测可比部分，包含线缆、紧固件、打印件填充、末端工具及负载，正确归属随哪根连杆运动。

静态重力主要依赖质量、重心和几何；惯量张量不必在第一阶段精确辨识，但后端要求的惯性参数仍应物理有效。重心的 URDF inertial origin 变换需正确解析。

保留原始暂定模型，新增带元数据的配置/覆盖文件。替代粗糙的 `allow-provisional` 一刀切开关：允许暂定模型做离线、shadow 及用户操作的受限方向验证；是否可用于正常补偿由坐标核验、误差预算和实测结果决定，不能直接改标签假装已标定。

## 4. 软件结构与接口决策

逻辑链路如下；模块名可按现有项目调整：

```text
实测状态 → 唯一坐标转换 → GravityModel / 可选 FrictionModel
        → 前馈斜坡与限制 → 完整 MIT 命令快照 → 现有唯一驱动写入口

现有面板 → 模式/配置请求 → 驱动确认状态
所有阶段 → 时间戳、分项力矩、原因码与日志
```

算法模块应能脱离串口、CAN 和 ROS 单独调用，提供至少 `load_model()`、`compute_gravity()`、`compute_friction()` 和模型元数据。模型加载、磁盘访问与昂贵辨识不进入控制循环。算法计算可在现有循环内或独立 worker 中运行，但必须只保留一个硬件命令仲裁与发送入口；worker 结果携带状态序号、计算时间和有效期。

接口决策：配置/模式切换优先沿用现有有确认机制的 service 或参数事务；高频命令和状态用带时间戳、序号的 topic/现有控制接口。不要为追求形式重写整个通信框架。若现有 gain topic 扩展能可靠完成，也可沿用，但必须加入确认和原子应用语义。

至少具备以下字段，类型与字段名按项目规范定义：

| 类别 | 逻辑字段 |
| --- | --- |
| 命令 | 关节名、q_des、v_des、kp、kd、tau_ff、mode、seq、有效期 |
| 配置 | alpha、beta、斜坡、模型 ID、负载 ID、阈值配置版本 |
| 状态 | 请求序号、已应用序号、请求值、实际应用值、拒绝原因、状态数据年龄 |
| 诊断 | tau_g、tau_friction、PD 分项、合成估计、保守包络、饱和标志、循环耗时 |

四轴配置先整体校验再原子应用，避免一半新 Kp、一半旧前馈。按已有控制器所有权实现互斥，防止旧 gain 发布者、轨迹客户端和扫描程序争写。重启不重放历史非零前馈，过期请求不执行；退出、清错后不自动重新使能。

面板至少包含：模型/重力方向/负载状态、逐轴重力与摩擦估计、已应用前馈、补偿开关与系数、shadow 模式、门禁余量、饱和/拒绝原因、日志开始停止、受控停止和现有急停入口。不要把完整调参页重构作为重力补偿的前置阻塞。

## 5. 门禁重新设计：允许改，但先把公式和含义弄对

### 5.1 纠正来信中 `Kd·v` 的判断

来信用 `Kd=5`、`v=0.25 rad/s` 得到 1.25 N·m，乘法成立，但解释取决于实际报文：

- 若电机 `v_des=0`，内部 D 项确实对运动产生约 `-Kd*v` 的阻尼，位置 P 项可能需要克服它。
- 若发送的是 `v_des≈v_measured≈0.25`，内部 D 项接近零，不能仍按 1.25 N·m 当作实际必然输出。
- 若门禁故意使用绝对值相加作为最坏包络，1.25 可能属于保守检查量；需要明确标为包络，不能当成测得力矩或真实合成力矩。

因此，来信中 J3/J4 “只剩约 0.13°”的结论在查清实际 Kp、速度目标、坐标、估计公式前暂不采纳，必须重新计算。先修正模型和速度通路，再决定是否提高门禁。

### 5.2 将三类量分开显示

```text
tau_pd_est = Kp*e_q + Kd*e_v
tau_total_est = tau_pd_est + tau_ff_applied
tau_abs_envelope = abs(Kp*e_q) + abs(Kd*e_v) + abs(tau_ff_applied)
```

分别记录有符号合成估计、保守包络和独立实测/反馈力矩。保持同一侧单位，角度误差处理符合关节类型。通过反馈新鲜度与误差边界评估不确定性；上位机估计不能冒充驱动内部硬力矩钳位，也不能利用分项相消掩盖过大的增益或跟踪误差。

### 5.3 门禁策略与修改记录

| 类型 | 本任务处理 |
| --- | --- |
| 历史软件估计门禁，如 8/10/2/2 | 可改为配置，可修正过度保守公式；先确认来源，再给新值或待确认项 |
| 单项限制 | 分别设置前馈幅值、前馈变化率、Kp/Kd、速度、加速度、位置误差与状态年龄范围 |
| 总量/硬件能力 | 依据具体电机、驱动、齿比、持续时间和结构，核查协议范围、连续/短时能力，不凭门禁值推断 |
| 机械与故障保护 | 保留有效的行程、失联、急停、温度/电流等机制；修正配置时保持功能，不空函数绕过 |

前馈限幅和变化率限制允许实现，并显示 requested/applied 与原因；发生限制时该点不能按“完整重力补偿通过”统计。超出总能力、严重跟踪异常或状态失效时进入明确故障流程；不把危险命令静默裁剪后继续伪装正常。

严重故障不使用普通斜坡延迟必要动作。普通开关补偿时采用平滑过渡；有负载的机械臂不能把“所有故障立即清零并失能”当作普遍安全方案。根据现有制动/支撑条件定义受控减速、保持、交接支撑与失能的顺序；通讯彻底丢失时靠已验证的驱动看门狗/制动策略，不能声称上位机还能保证保持。

为每个变更形成表格：旧值、新值、公式/来源、适用模式、离线测试、待实机验证、回滚位置。硬件能力无依据时不编造新 N·m 上限。

## 6. 分阶段实施，完成一阶段再进入下一阶段

### A. 基线、模型和 shadow

完成接口核查、坐标模块、重力计算、配置、日志与面板。shadow 使用实际/回放状态计算并显示，但不改变原有电机命令。通过 mock 验证开关关闭时与基线一致；完成单摆解析校验、势能差分与符号/单位测试。

不得把来信中起点和“+10°点”力矩硬编码为真值；确认 +10° 的具体关节组合，附模型与配置哈希后再做回归。

### B. 接通重力前馈，准备用户实机操作

完成驱动最小必要补丁，让非零 `tau_ff` 真正进入 MIT 报文字段；在 PTY/mock 层捕获报文并解码验证。默认保持原有 Kp/Kd 和位置保持模式，重力补偿为可开关前馈。普通启用时捕获/沿用一致的目标，避免跳变；不自动把 Kp 降到零。

给用户准备受支撑、低风险范围内的操作步骤：先确认机械安装与基础坐标，再选择预测力矩明显非零、远离限位且无外部接触的姿态；从较小补偿比例渐进，观察同姿态下 P 项需求、误差和运动方向。单个姿态的力矩符号不能唯一辨识全部重力方向、零点和质量，要用多个独立姿态综合核验。

暂定模型可用于上述受限验证，不直接进入全工作空间大比例补偿。现场数据未到时，软件保持“离线通过、待实机核验”的准确状态，提供日志采集入口；不要因此留下未接通的前馈接口。

### C. 质量/重心修正与重力验收

结合可测总质量、CAD 重心、工具负载和多姿态保持/缓慢双向数据修正模型。单次静止保持力矩混有静摩擦，不能直接全归为重力。需要辨识时优先质量×重心的一阶矩/可辨识组合参数，报告激励不足和残差，不声称仅靠称重或两姿态就恢复所有连杆重心。

不预设通用“质量必须 ±5%”“重心必须几毫米”门槛。根据工作空间采样和参数扰动给出重力矩误差范围，再与可用 PD 余量及实测残差比较。静态线性近似 `e≈Δtau/Kp` 只用于估算，不作为 0.5° 必达证明。

### D. 恒速扫描与摩擦模型

新增有界单轴实验客户端，沿现有命令仲裁进入驱动。一次只扫一个关节，其他关节保持；但四轴重力前馈都应随整臂实测姿态更新。采用加速—恒速—减速轨迹，显式设置行程、速度、加速度、持续时间、停止条件。恒速段采数据，加减速、换向、饱和、接触和状态异常段剔除。

速度列表支持 0.05 / 0.12 / 0.25 rad/s，并先小后大。J3/J4 的 0.25 是否可用由修正后的命令、阈值与硬件预算决定，不再因旧门禁一概禁止；也不为跑满三档强行扩大硬件能力。若无足够行程达到目标速度并留下恒速采样区间，该实验标为不可行或降速，不伪装成恒速数据。

草图中的 `±0.3` 含义未知，不作为隐藏默认值。软件分别提供带单位的 `scan_amplitude_rad`、`friction_limit_nm`；离线可先使用明确标注的示例，实机运行参数必须由用户在实验入口设置/核对。

在统一关节坐标、无接触条件下，恒速段可拟合：

```text
f_residual ≈ tau_feedback_joint - g_model(q)
f_model(v) = Fc*tanh(v/v_eps) + B*v
```

这是第一版简化模型；加速度显著时还需考虑 `M*q_ddot+C*q_dot`，不能全部叫摩擦。若有可信动力学后端，可计算并扣除这些项。三档正反速度可拟合基础库仑+粘滞模型，不足以证明精确辨识 Stribeck、温漂、预滑或载荷相关摩擦。

同姿态/姿态分箱的正反向数据可帮助分离重力与对称摩擦，但需说明对称假设；不对称残差保留在报告中。至少保留一部分独立数据检验拟合，图中区分拟合数据与验证数据。

重点：若 `effort_estimate` 本来由 `Kp*e+Kd*e_v+ff` 重构，它与命令有同源性，只能作为初步命令残差模型，不能冒充独立测得的摩擦或测得力矩。反馈力矩比例未知时继续提供采集/拟合软件，并明确标记辨识结果的适用限制。

摩擦补偿第二阶段才启用，使用平滑零速处理、独立系数与限幅；静止时不凭位置误差自动选择一个库仑符号。不默认添加积分器，不在首次重力验证时同时改 Kp/Kd 和摩擦。

## 7. 模式、时序和停止行为

实现可观察的模式/状态，具体命名按项目规范：disabled、shadow、hold_gravity、scan、fault。轻拖动如实现，使用单独模式及独立增益配置，另行验证稳定性，不能直接宣传为已完成的重力保持功能。

状态超时、计算超时、NaN/Inf、维度错误、关节缺失、模型加载失败、重复写入者、非法序号都要有确定行为和原因码。重力 worker 不能无限沿用旧姿态力矩。恢复后需要明确重新启用流程，不自动恢复扫描。

复用并测量现有控制周期，提供计算与端到端耗时、状态年龄的 P50/P95/P99、最大值和漏周期计数。不要写未经实测的“WSL 保证 1 kHz 实时”。数据有效期与看门狗阈值依实测周期和现有驱动能力制定，并以故障注入验证。

受控停止时先按模式终止轨迹并执行已定义的保持/制动流程；用户急停、严重故障优先走既有有效的急停机制。报告“命令已发出”和“反馈确认已停止”的区别。只有离线 PTY 时，标注是模拟确认。

## 8. 必须交付的内容与验收

文件组织按现有项目，不要求为凑目录另建一套项目。至少交付：

1. 重力计算与坐标模块，包含模型/负载加载、来源、单位、配置版本与哈希。
2. 现有 MIT 驱动的前馈接入和唯一仲裁；必要的有确认配置接口。
3. 现有上位机中的重力补偿操作页/区域、状态、诊断与日志。
4. shadow、回放、恒速扫描、离线拟合工具及明确运行入口。
5. 配置样例、依赖/构建说明、参数说明、回滚步骤和用户实机操作说明。
6. 离线测试结果与已知未验证项；禁止将离线通过写成实机通过。

离线测试围绕实际风险，不仅验证计算函数返回了四个数：

| 验收项 | 必须提供的证据 |
| --- | --- |
| 重力公式 | 已知单摆/简单链解析结果；姿态变化、零重力、负载变化；势能中心差分与解析重力一致 |
| 符号与映射 | 四轴方向、零点、J3 偏置只应用一次、齿比、力矩虚功一致、按名称映射 |
| 后端对照 | 条件允许时两个独立后端，统一模型后比较；无法完成时列出原因和解析/差分替代证据 |
| MIT 端到端 | mock/PTY 捕获并解码非零前馈、v_des、增益；禁用前馈时原路径兼容，无重复 PD |
| 门禁 | 正负方向、分项抵消、真实速度误差、边界、前馈斜坡/饱和，超限原因与实际动作 |
| 故障处理 | 旧状态、计算卡住、节点退出、NaN、重启、重复写入者、停止/故障锁存行为 |
| 扫描与拟合 | 轨迹不越界、实际存在恒速段、仅单轴扫描；已知摩擦参数的合成数据可恢复并报告残差 |

纯数值重力对照可从 `abs_error ≤ 1e-5 N·m + 1e-4*abs(reference)` 作为初始测试目标，势能差分需要选择步长并检查收敛；该容差只针对数值一致性，不代表模型接近实机的精度。若模型转换或数值精度导致不适用，解释原因并给出新的可复现标准。

用户实机验收模板：同一模型、同一负载、同一目标姿态/轨迹、同一 Kp/Kd，对比关闭/开启重力，之后才对比加入摩擦。预先定义稳定窗口和采样方法；记录各轴稳态绝对误差、RMS/最大误差、速度/振荡、前馈与 PD 分项、反馈来源、饱和比例、停止结果和温度/电流（若可读）。

0.5°保留为位置保持的稳态目标，写明统计窗口与适用姿态；动态轨迹的 RMS/峰值指标另列，不能把 0.5° 无区别套在所有瞬态上。重力成功还要看模型方向正确、PD 保持负担/偏差改善、无异常振荡及力矩能力满足。单纯增大 Kp 压到 0.5° 不算重力算法验收通过。模型误差/摩擦导致目标未达时，交付真实结果和下一步修正，不伪造达标。
