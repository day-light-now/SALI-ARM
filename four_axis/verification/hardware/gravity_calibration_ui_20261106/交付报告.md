## 2. 驱动修改（两个独立提交）

### 2.1 `d903fce` fix(float): qualify hand-drag readiness by completed feedforward ramp

- `hold_ready` 在自由拖动模式改为：前馈渐入完成即就绪；正常位置保持仍为“静止 0.5 s + 增益斜坡”，保留抓取/保持就绪语义。
- 依据：任务书要求复核驱动自由拖动就绪语义；参考 `438a05a` 第一项。
- C++ 反例：0.2 rad/s 持续拖动 → 位置补偿渐入后 `HOLD` 且 `hold_ready=1`；位置模式 0.2 rad/s 仍不能就绪。CTest 5/5（修复后单独构建验证）。

### 2.2 `801d3d0` feat(float): skip position-mode feedback speed gate during hand dragging（独立评审项）

- 自由拖动期间不再用位置模式 1 rad/s 反馈速度门限中止；位置模式保留原门限。温度、反馈年龄、周期间隙、MIT 时序、URDF 限位、表示范围、会话超时、全轴停止均保留。
- C++ 反例：自由拖动 1.2 rad/s 保持 `HOLD`；位置模式 1.2 rad/s 仍 `FEEDBACK_SPEED` 全轴停止。CTest 5/5。

## 3. 网页当前位置静态采样（单一所有者有限操作）

实现文件：`supported_capture.py`、`commission_supported_trial.py`、`control_panel.py`/`control_panel_http.py`/`control_panel_model.py`、`web/control_panel/{index.html,panel.js}`、`calibration_capture.py`/`calibration_core.py` 的“窗口可诊断”扩展、`calibration_session.py` 的大角度组。

流程：
1. 操作员结束自由拖动/示教 → 等待新失能确认 → 软件复位到新鲜未使能；
2. 网页预览冻结当前实际姿态：四轴角度、完整限位、运行身份（boot/哈希/load_id）、Kp/Kd、α 基线、有限时间（撤手等待 60 s、静态窗口 2 s/10 帧、会话估计 76 s）；
3. 服务端校验票根、起点漂移（≤0.5°）、身份、停止纪元后启动受保护客户端；客户端 `arm_supported_current_pose`（正常位置保持 Kp=160/Kd=5），等 stage=5 且 `hold_ready`，记录模式/目标/回执；
4. 页面显示“位置保持已就绪，托稳后缓慢撤手”；操作员撤手、支撑不承重后勾选并点击；
5. 面板校验 operation/running/阶段/新鲜/命令 ID/boot/身份/停止纪元/未重复后写一次性 ack 文件（schema + operation_id + command_id + boot_id + identity_sha256 + panel_stop_generation + nonce + operator_disengaged）；客户端校验后采集静态窗口；
6. 停止优先：先全轴停止并确认新失能，再独占创建只读原始 JSONL（来源身份、窗口质量、α、残差）；操作结束展示质量、拟合资格、原始文件与“反馈力矩 − 候选模型”只读残差。

关键约束：
- α=0 才可进入既有静态拟合；α=0.1 的实机普通位置保持样本允许保存但标记“仅诊断”，`calibration_core.exclusion_reason` 继续拒绝 alpha≠0。
- 拒绝矩阵（服务端 + 客户端双重）：跨停止纪元、换 boot/command/身份、反馈过期/失联、阶段非保持、未就绪、重复 ack、操作结束后 ack、采样后 ack、心跳丢失、UNKNOWN；任何阶段停止都终止客户端并拒绝迟到 ack。
- 本轮未新增参数、未写质量档案、未改部署；实机 α=0.1 时页面明确显示“基线不满足：仅诊断”。

## 7. 边界、未决事项与建议

1. **实机 α=0.1**：页面会显示“基线不满足：仅诊断”；实机只有把普通位置保持的 `gravity_ff_alpha` 设为 0，静态样本才可进入拟合。该参数切换属于部署决定，未在本轮执行。
2. **速度门限**：`801d3d0` 是独立安全策略放宽，建议由 Codex/用户单独决定是否上线；不随就绪修复默认视为已接受。
3. **大角度新参数**：仍需要现场按方案采集 L01–L04/V02；本轮只提供计划、校准组、门槛与只读分析，没有新参数可部署。
4. **静态采样 UI**：为受保护有限操作，仍不是物理急停；现场需防坠支撑、净空与断电手段；操作员必须确认“已撤手、支撑不承重”。
5. **失败操作归因**：就绪超时已由 `d903fce` 解决；写监督异常与速度门限事件是另外两类问题，不应与本轮修复混为一项。
