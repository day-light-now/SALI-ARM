# Codex 交接复核

复核源码 HEAD `15bc3e9`，包含交接摘要 `404d71d` 之后的重力模型输入夹限修改。现场只读检查发现 stage=9、四轴反馈无效，与交接中 stage=8 的历史快照不同。已收到用户现场支撑并切断电机电源的确认。本轮执行代码检查、原始数据哈希核对、纯数学交叉验证和 FakeNode 面板回调反例。

## 阻断项

### P1 停止后仍可发布旧纪元撤手确认

`control_panel.py` 的 `ack_supported_capture()` 在写文件前验证停止纪元，写入与发布期间没有最终停止纪元和操作有效性复核。反例在真实 `write_ack_file()` 发布前触发 `_request_stop()`，得到 accepted=true、cancel_requested=true、当前 generation=1、确认文件 generation=0。客户端按旧 CLI 纪元核对该文件，可能继续接收旧确认。

需要在磁盘准备完成后，将最终发布与停止状态校验序列化。停止路径保持有界，文件 I/O 放在停止关键区之外。补上并发停止、重复请求及操作结束期间发布确认的回归测试。

### P1 静态窗口没有绑定已确认的命令与运行身份

`commission_supported_trial.py` 校验撤手 ack 后调用 `collect_static()`，没有逐帧核对 ack 所属 command_id、boot_id、身份指纹。`calibration_capture.py` 遇到新 command_id 会清空旧窗口并继续等待新窗口，可能把另一条命令下的静态窗口归于旧撤手声明。

需要把已确认身份传入采样边界，逐帧匹配。窗口内身份或命令变化应明确中止该操作，保存诊断结果。补上换命令、换 boot、换配置的真实采样入口反例。

### P2 首次就绪覆盖预览冻结身份

`_launch()` 保存预览身份后，`_check_supported_capture()` 在第一次 ready 时以当前身份覆盖 `capture_identity_sha256` 和 boot。反例在首次就绪前更换 boot/mapping，仍可确认撤手。客户端也没有接收到预览身份用于使能前复核。

需要分别保存预期身份和观测身份，保持预览的确认对象，并在客户端使能前核对。首次就绪发现身份变化应要求重新预览。

两项真实面板回调反例与结果保存在本目录 `codex_handoff_counterexamples.py` 和 `evidence/codex_handoff_counterexamples.json`。它们使用 FakeNode 和临时文件，终止进程方法打桩。

逐一核对旧、新候选 sources 中所有原始文件 SHA256，按相同正反来向配对均值口径评估。

|---|---|---|
| 原 V01，2 个配对 | 0.157591 | 0.301653 |
| 新 V02，2 个配对 | 0.408318 | 0.175500 |

新候选在大角度留出上改善，原小角度留出则退化。V02 中 `[12,6,0,0]` 与训练中的低姿态重复，新增大角度留出姿态实际只有一个。下一版报告应同时评估原 V01 和新 V02，并说明覆盖、重复姿态和模型取舍。现场进一步采样与模型应用交后续验收。

完整逐轴指标见 `evidence/codex_model_cross_validation.json`。复算脚本为 `codex_model_cross_validation.py`。

## 部署与复现

- 现场进程 PID 408977 的映射库 inode=200461，路径标记 deleted。磁盘上的库 inode=200581、SHA256 `63f1fcb9e55623825b18d20d5233c9636bfe8fb954bcf90848a86cd8041448b0`。本次检查时运行进程使用重建前的库，磁盘新库哈希不足以证明新代码已加载。
- 部署目录中 `calibration_capture.py`、`calibration_core.py`、`calibration_session.py` 与源码有差异，涉及所选重力档案身份、LOCAL_OFFLINE_CANDIDATE 状态、组末低姿态目标。需要纳入源码与测试后重建。
- `fit_large_angle_campaign.py` 从固定部署目录导入模块，并用当前安装档案做旧模型和捕获身份比较。部署新模型后，只读调用其 `load_campaign()` 已复现 `AssertionError: analysis resources differ from capture identity`。拟合应改用显式输入资源和捕获时冻结的档案，避免依赖当前部署状态。
- stale robot_state_publisher 可以解释旧 URDF/身份污染。串口写异常、就绪超时、模型越限异常需继续按审计事件分别核对。

## 当前结论

大角度采集与新模型 V02 改善的记录有对应证据。撤手确认与身份绑定存在上述返工项，候选模型和部署资源仍需完成可复现验收。双机遥操方案作为设计输入保留，主从关系、松灵型号、SDK/上位机扩展方式及通信接口资料齐全后再确定适配与仲裁实现。
