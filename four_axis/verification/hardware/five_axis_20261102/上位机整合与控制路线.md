# 上位机整合与控制路线（2026-11-02）

## 1. 为什么要整合

现在桌面有三套东西：

- **Codex J4 原生 MIT**：2026-11-02 10:19 实机受支撑往返已通过，Kp160/Kd5/1.0，J4 单轴；
- **DeepSeek 五轴**：J1–J4 同时原生 MIT，J4 用 Codex 已测 160/5/1.0，J1–J3 用 32/2/0.2 模板；J5 关闭；10:48 J1–J4 保持 2s 已通过；
- **PySide6 桌面上位机**：仿真/四轴只读，实机运动网关关闭。

它们都要独占 COM9。没有统一入口时，容易同时打开两个窗口、抢串口，或者在错误的窗口里点错模式。所以上位机第一职责不是“多发指令”，而是**模式隔离 + 单一 COM9 所有者 + 清楚的证据标签**。

## 2. 上位机结构

`启动桌面上位机.vbs` → `slai_console.launch` → **“SLAI 机械臂上位机 · 模式切换”**。

| 模式 | 后端 | 边界 |
|---|---|---|
| DeepSeek 五轴 | `five_axis_console` | J1–J4 原生 MIT；J5 关闭；实验路径 |
| Codex J4 原生 | `native_mit_console` | J4 单轴；已实机单次往返；已知良好基线 |
| PySide6 上位机 | `app` | 仿真/四轴只读；无实机运动 |
| 主机 PD 受限接管 | `live_trial` | 旧主机 PD 诊断，非原生 MIT |
| J4 保护测试 | `watchdog_check` | 看门狗/保护诊断 |

规则：

- 上位机壳**不连接串口、不使能、不发帧**；
- 子程序运行期间其他模式禁用；关闭子程序窗口后才能切换；
- 每个模式自己的支撑/净空/原生输出票据仍然有效，上位机壳不能代替；
- 不允许 Codex J4 与 DeepSeek 五轴同时连接 COM9。

## 3. 当前控制逻辑（DeepSeek 五轴）

### 3.1 执行位置

驱动内部 MIT：PC 发 `q/dq/Kp/Kd/tau_ff`；驱动内部 PD；主机不做 PD 力矩。J4 的 160/5 是实机测过的；J1–J3 的 32/2 只是保守模板，不是实测。

### 3.2 逐轴包络

- 目标速度 ≤0.02rad/s；反馈速度中止 J1–J3/J5 0.2rad/s、J4 1.0rad/s；
- 跟随误差 ≤4°；温度 ≤50°C；反馈年龄 ≤60ms；主机间隔 ≤40ms；
- 每轴 2Nm **观测点请求估计**护栏、4Nm 反馈力矩护栏；不是驱动内部连续力矩硬限幅；
- 行程：J1–J4 在 `core.LIMITS` 内再收窄；J5 未标定，不进入 active。

### 3.3 使能/保持/轨迹/速度

1. 控制前对 active 轴做**并发新鲜预检**（≤30ms）；
2. 当前位置接管；逐轴预置 MIT（kp=kd=0）→ FC → 状态1 → 1s 增益斜坡；
3. 保持：当前姿态 2s；
4. 轨迹：minjerk，逐段峰值速度 ≤0.02rad/s；目标填**绝对模型角**，UI 已加“目标=当前+0.5°”按钮，避免把 0.5 当相对量；
5. 速度：需要额外勾选“额外接受速度模式”；kp=0、kd 驱动内部速度环；不作为第一条试验；
6. 故障/停止：FD 全部 active 轴 → 等新反馈 state0 → DISABLED；超时 UNKNOWN 锁定，不自动重连；异常停止也跑确认。

### 3.4 已经证明的与还没证明的

已证明：

- J4 单轴受支撑往返（Codex，10:19）：9.857°，回差 0.306°，DISABLED；
- J1–J4 同时使能/保持 2s（DeepSeek，10:48）：四轴 ENABLED、HOLD、FD、DISABLED；
- 速度模式在未勾选时拒绝且不发速度命令；轨迹速度检查拒绝时正常 FD/DISABLED；
- 新鲜预检修复了只读轮询导致 J1 反馈 0.22s 过期的问题。

未证明：

- J1–J4 实际协调位移（0.5° 轨迹还没走成；两次都是绝对值填错被速度检查拒绝，不是电机故障）；
- J1–J3 的增益/护栏是否适合带载；
- J5 方向/零位/限位（mapping 仍是 null，J5 未接）；
- 驱动内部连续力矩/电流硬限幅；重力补偿；多段轨迹；长时间可靠性。

## 4. 控制逻辑上真正要改的地方

1. **目标量纲**：绝对角/相对角混用是这几轮的主要操作错误。UI 默认给“当前+0.5°”按钮；后续可把轨迹页改成“相对增量”输入，绝对角只读显示。
2. **J1–J3 不是 J4 的复制品**：J4 的 160/5 是 J4 的实机结果；J1/J2 是 10010，J3 是 8009，负载/惯量/静摩擦不同。J1–J3 的 32/2 只是起点；先用小角度看跟随/估计/停止，再逐轴调，不能一次把 2Nm 跳到很大。
3. **2Nm 估计护栏不是硬限幅**：它只看当前反馈点的请求估计；真正连续力矩边界未核实。J1/J2 保持通过说明当前姿态/支撑下够用；带载或大角度可能先停，这是安全门，不是“电机没力”。
4. **速度模式最后做**：位置/轨迹稳定前，速度模式只会增加不可控因素；它需要单独的 ack，且默认不参与第一条试验。
5. **J5 是独立标定问题**：J5 的 sign/zero/limits 未验证；不能从 J4 数据推断，也不能用 OpenArm 的零位代替。接上后走四姿态手动标定，再把 `j5_enabled` 打开。
6. **模式隔离**：Codex J4 与 DeepSeek 五轴不要同时开；上位机的单 COM9 规则要成为操作习惯，而不是靠记忆。

## 5. 最终目标

不是“OpenArm 7 轴/夹爪/MoveIt/750Hz 整机等价”，而是一个**可验证的五轴（J1–J5）原生 MIT 上位机**：

1. 一个上位机内切换 Codex J4 基线与 DeepSeek 五轴；
2. J1–J4 协调：0.5° → 1–2° → 多段；逐轴跟随/停止/日志通过；
3. J5 接上后：四姿态手动标定 → 单轴/保持 → 并入五轴；
4. 逐轴增益/护栏适配；可选重力前馈/速度模式；
5. 全程保留：FD、新反馈 DISABLED、UNKNOWN 锁定、审计、单 COM9、支撑/净空票据；
6. 不声称驱动连续力矩硬限幅、重力补偿、整臂负载保持或 OpenArm 整机等价。
