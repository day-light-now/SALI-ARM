## 2. 官方原生 MIT 与本项目主机 PD 的数据流差异

官方（ROS2 + openarm_can）：

1. `OpenArmHW::write()`（`openarm_simple_hardware.cpp`）把 `{kp_[i], kd_[i], pos_commands_[i], vel_commands_[i], tau_commands_[i]}` 组成 `openarm::damiao_motor::MITParam`，调用 `openarm_->get_arm().mit_control_all(arm_params)`。
2. `DMDeviceCollection::mit_control_one()`（`dm_motor_device_collection.cpp`）检查 `ControlMode::MIT`，调用 `CanPacketEncoder::create_mit_control_command()`。
3. `pack_mit_control_data()`（`dm_motor_control.cpp`）把 kp(0..500)、kd(0..5)、q(±pMax)、dq(±vMax)、tau(±tMax) 量化进 8 字节；`double_to_uint()` 先 `limit_min_max` 再量化。
4. 总力矩由**驱动器内部**按 `kp*(q_des-q)+kd*(dq_des-dq)+tau_ff` 计算，并受驱动器自己的 TMAX/OC 等内部限制。CAN 报文没有“总力矩上限”字段；`tau` 只是前馈项。

本项目（`actuation.py`）：

1. 主机读 8 字节反馈，按 `p.sign` 转成模型位置/速度；`FourAxisController._torque_frame()` 在主机算 `kp*(target-q)+kd*(v_ref - sign*v_fb)`，再按 `torque_raw_bounds()` 选 12 位编码值，把驱动 kp/kd 字节写成 0、目标速度写 0、只写 tau 字段。
2. 因此驱动收到的是“纯前馈力矩”，闭环在主机；主机能对**总编码力矩**做限幅，这正是当前 1Nm/2Nm 候选能守住命令边界的原因。
3. 主机约 100Hz、Windows/USB 链路、反馈年龄 ≤60ms；官方示例 `update_rate: 750`、`interpolation_method: "none"`，是 Linux/CAN-FD 下的高频率参考。不能照抄 750Hz，也不能声称实时保证。

结论：生产入口继续用主机 PD + 总编码限幅。原生 MIT 只能做离线评估/原型；在不改电机参数（TMAX/OC/模式）的前提下，主机无法给原生 MIT 的总输出加上 2Nm 边界——只限 `tau` 字段不等于限总力矩。**不把生产入口悄悄改成驱动增益。**

## 3. 日志证据与本次问题定位（不宣称唯一根因）

三份真实记录的共同现象：

- 关节长时间不动，命令力矩在斜坡上慢慢升到 0.435Nm（1Nm/0.1）、0.989Nm（1Nm/0.2）、1.2Nm（2Nm）；
- 在某一帧位置码突然跳 6–9 个码值，同时反馈速度从 ±0.011/0.033 跳到 0.2088/0.1648 rad/s，保护在**这一帧**触发；
- FD 后仍有新反馈：2Nm 例首帧位置码 31671、速度 −0.4725，随后 31663，位置再走约 0.44° 才停；1Nm/0.1 例首帧速度 −0.2308、位置码 31695；
- 1Nm/0.2 例在 0.989Nm 饱和 0.29s，只有 0.044°（3 个码值）变化，跟随误差到 2° 停止；这不是“有效运动”，旧指标却给了 `MOVED`。

解释边界：

- 位置码跳变与速度突跳发生在同一 10ms 帧，主机在跳变前没有中间速度帧；所以“在 0.2 边界内提前刹车”对这几例不成立，除非降低释放前的力矩或改变起动策略；
- 对称斜坡把“增力”和“减力”都限制在同一速率，理论上会延迟释放后的减力；但真实记录在释放帧就 FD，记录里没有“释放后继续给力矩”的命令序列。合成原型还显示：**单纯把下降斜坡改得很快，可能让力矩掉到动摩擦以下，造成粘滑反复，峰值速度反而更大**。所以不能把“对称斜坡延迟”当作已证实的唯一根因；
- 速度反馈是驱动估计值，量化步长 0.011/0.033 rad/s；位置码分辨率 0.02186°。少量码值变化不能当有效运动；
- 驱动力矩反馈是估计值，不是轴端测力；用户确认断电可手动转动，也不能排除负载/支撑/弹性/机械问题。

## 4. 选择的控制结构

**生产路径不变**：主机 PD（Kp=32、Kd=0.5 的候选档），总编码力矩 ≤ 所选档（1/2Nm），驱动 kp/kd=0。只新增**明确选择**的“有界起动/阻尼候选档”，不改已有 1Nm/2Nm 档，不改 `actuation_io.py`、网关或保护阈值。

新增两个候选档：

- `kp32_1nm_brake_candidate`：1Nm，Kp=32/Kd=0.5，速度中止 0.1rad/s，跟随误差 2°，与既有 1Nm 档相同的边界；
- `kp32_2nm_brake_candidate`：2Nm，Kp=32/Kd=0.5，速度中止 0.2rad/s，跟随误差 4°，与既有 2Nm 档相同的边界。

两档共用一个 `CandidateControl`（冻结在档位里，随票根和确认绑定）：

| 参数 | 1Nm 档 | 2Nm 档 | 理由 |
|---|---|---|---|
| `slew_up_nm_s` | 0.5 | 1.0 | 与既有档一致，不加快增力 |
| `slew_down_nm_s` | 10.0 | 10.0 | 有界快速减力；只作用于**减小**，增力仍受上行速率限制；FD 不受任何斜坡 |
| `startup_cap_nm` | 0.5 | 1.0 | 起动阶段（未确认运动前）的相内上限，低于档位总上限；不自动升到总上限 |
| `startup_window_s` | 6.0 | 6.0 | 有界起动尝试；3s 会在观测到的 1Nm 释放前（4.16s）就停，6s 允许有界尝试且仍早于 2Nm 4° 误差停止（约 7.3s）；届时仍无确认运动则受控停止并报告，不自动延长/升力 |
| `motion_confirm_codes` | 3 | 3 | 0.0656°，高于观测到的 1–2 码抖动；确认后解除起动相上限 |
| `brake_gain_nm_per_rad_s` | 2.0 | 2.0 | 有界速度误差阻尼，只在跟踪段生效 |
| `brake_cap_nm` | 0.30 | 0.40 | 阻尼项上限，远小于档位总上限 |
| `brake_deadband_rad_s` | 0.05 | 0.05 | 高于 0.011/0.033 的速度量化噪声，避免静止抖动 |

控制律（每轴、每 10ms 周期）：

1. `requested = kp*(target-q) + kd*(v_ref - sign*v_fb)`（与原主机 PD 相同）。
2. 起动相：若该段轨迹已开始、尚未确认运动（沿该段方向的位移 < `motion_confirm_codes` 个码值），把 `requested` 限到 `±startup_cap_nm`；不改变真正的跟随误差保护（保护仍用真实 target−q）。
3. 阻尼：若 `|sign*v_fb| - max(|v_ref|, deadband) > 0`，从 `requested` 减去 `min(brake_cap, brake_gain*excess)`，方向与测量运动相反。该项只耗散，不增加沿运动方向的能量；总命令再限到档位上限。
4. 斜坡：`torque` 相对上一周期输出，增加时按 `slew_up`，减小时按 `slew_down`；快速下降路径不被增力上限阻塞。FD/紧急失能完全绕过这一步。
5. 编码：仍用 `torque_raw_bounds()`，总编码绝对值 ≤ 所选档；12 位量化后实际可达 0.989Nm（1Nm 档）/1.991Nm（2Nm 档）。
6. 起动窗口：若轨迹开始后 `startup_window_s` 内仍未确认运动，抛 `Startup no breakaway ...`，走既有全局停止/FD/新反馈确认路径。不自动升档、不自动延长、不重试。

PD 执行位置：**不变**，仍在主机；驱动 kp/kd 仍为 0。没有把原生 MIT 增益放进生产路径。

## 5. 诊断改造（任务 D）

- `motion_class`：`NO_CODE_CHANGE` / `CODE_JITTER`（<3 个码值或净位移 <0.0656°）/ `OBSERVABLE_START`（≥0.0656° 且 <1°）/ `PARTIAL_TRACKING`（≥1° 且 <5°）/ `EFFECTIVE_TRACKING`（≥5°）；保持 `NO_MOTION_REQUIRED`（保持试验）。
- `moved` 只对 `OBSERVABLE_START` 及以上为真；0.044°/3 码的 1Nm/0.2 例应归为 `CODE_JITTER`，不得称有效运动。
- 新增 `trigger_frame`：触发保护那一帧的 state、位置码、模型角、原始/模型速度、跟随误差、当时在用的编码命令、原因。用 `c.last_snapshot`（触发 tick 实际使用的反馈）。
- 新增 `post_stop_*`：停止后新反馈帧（state/code/角度/速度/相对时间）、首帧、末帧、停止后位置变化、停止后峰值速度。由 `finally` 在等待 DISABLED 的循环里采集。
- 报告摘要包含“保护触发帧”和“停止后新反馈”，不再只报保护前的 0.13°。
- 成功判据不变：真实 10° 出程、0.5° 到位、返回起点、新反馈确认 DISABLED；抖动/静止不算成功。

## 7. 测试计划（先写后实现）

1. 旧/新斜坡：同一 `previous=1.2Nm`、`demand=0`、`dt=10ms`，旧对称 1Nm/s 需 120 周期（1.2s），新 10Nm/s 需 12 周期（0.12s）；新算法在 2 周期内下降 ≥0.2Nm，旧算法 <0.02Nm。
2. 真实日志只读回放（`tmp/live_trial/20261101_155927_e9ad73` + 原始反馈）：取出触发帧命令 1.2Nm、位置码/速度；断言旧 shaper 减到 0 的周期数 ≈120，新 ≈12；断言原始日志在停止后有 state=0、|v|≥0.4、相邻码值变化 ≥8 的帧，证明“停止后仍运动”被保留在诊断里；断言 155439 的 0.044° 被分类为 `CODE_JITTER` 而不是有效运动。
3. 合成 plant（粘滑 + 惯量 + 阻尼 + 16 位位置/12 位速度量化 + 1–2 周期反馈延迟 + 有界抖动）：
   - fs=1.2Nm、2Nm 档：旧档在约 6.2s 释放并触发速度保护；新档在 6s 起动窗口内未突破 1.0Nm，受控停止、无速度突跳、停止后位移为 0，报告 `STARTUP_NO_BREAKAWAY`；
   - fs=0.9Nm：两档都能释放；新档（阻尼 + 快速减力）峰值速度 <0.20 且继续跟随 ≥5°，旧档在 0.2 中止且位移 <1°（以原型为准，测试中固定种子，若实际不满足则报告失败并调低断言范围，不自动放宽保护）。
4. 硬性超速仍立即全停：在阻尼/快速减力生效时，|v| 超 0.1/0.2 仍立即 STOPPING+FD，不允许“先刹车几帧”。
5. 断连/旧反馈/异常回调/取消/参数变化路径不复活；J5 排除；默认档 Kp=4；无确认不发运动；编码输出 ≤ 档位上限；同一周期同一快照的身份/符号正确。

## 9. 实现后偏差

1. **起动窗口**：设计初稿 3s，后改为 6s。3s 会在观测到的 1Nm 释放（4.16s）前就停；6s 允许有界尝试且仍早于 2Nm 4° 误差停止（约 7.3s）。1Nm 档的 2° 误差停止约 5.9s，早于 6s，因此 1Nm 卡死时通常由跟随误差先停，而不是起动窗口；两种都按“未建立有效运动”报告。
2. **起动窗口误触发已修**：实现中发现“轨迹恰好到达（同一周期 plan 被置 None）后仍执行起动检查”，会把正常到达误判为 `Startup no breakaway`；已改为仅当 `self.plan is not None` 时检查，并加了生产路径回归。
3. **合成 plant 的适用范围**：6s 窗口/1.0Nm 起动上限在 J=0.15、fs=0.9 上可完成 18s 跟踪（峰值 0.1648rad/s、位移 8.72°），在 fs=1.2 上受控停止（峰值 0.033rad/s、位移 0）；在 J=0.05 的低惯量 plant 上仍会在 0.2 边界中止——按任务书报告失败与机械/惯量待确认，未放宽阈值。
4. **诊断字段**：因 `_check` 类故障（速度/状态/时效）发生在 `last_snapshot` 更新之前，`trigger_frame` 优先用 reader 当前故障帧；`post_stop` 用 `_drain()` 只读采集，未改 `actuation_io.py`。新增 `FEEDBACK_SPEED_ABORT` 等稳定码。
5. **运动分类**：0.044°/3 码（155439）由旧 `MOVED` 改为 `CODE_JITTER_NO_EFFECTIVE_MOTION`；0.0656°/0.1311° 为 `OBSERVABLE_START`；成功仍要求 9.5°/0.5°/返回/失能。
6. **Windows 测试环境**：`four_axis_monitor.Reader` 的秒+微秒日志命名在 15.6ms tick 下会碰撞；由测试层 `test_reader_fixture.py::make_reader()` 真实短 sleep 重试构造（不替换时钟），两个测试的 `TemporaryDirectory` 加 `ignore_cleanup_errors=True`；产品代码未改，报告已说明。
7. **原档位未动**：`kp32_1nm_candidate`/`kp32_2nm_candidate` 的对称斜坡、上限、速度/误差阈值保持；新增两个 `*_brake_candidate` 档。
8. **[第一轮返工] 过零分段**：Codex 反例 `previous=+0.01, requested=-2, dt=.01` 旧实现输出 -0.09/rate=10；现用 `asymmetric_slew`：先用 `down` 减到零（1ms），剩余 9ms 按 `up` 反向建力到 -0.009、rate=1、`reverse=true`。反向幅度不超过 `up*(dt-|previous|/down)`；FD 仍绕过。
9. **[第一轮返工] 起动复合/编码/锁存**：Codex 反例 `requested=-1, previous=-1, dt=.04, motion_confirmed=false, velocity=.19` 旧 `pre_slew=-1.28, torque=-1.04`；现在起动相 `limit=startup_cap` 在请求、阻尼后、斜坡后都生效，`_torque_frame` 也按 `limit` 选码，结果 -1.0/-1.0、编码 ≤1.0。`motion_confirmed` 改为每程锁存，`start()`/`trajectory()` 重置。
10. **[第一轮返工] 停止后采集**：主循环每 cycle 后立即采集可见帧；仅四轴新反馈确认 DISABLED 后，0.30s/最多 32 次 J4 `0x7FF 04 00 CC` 只读轮询（记录 TX/RX）；UNKNOWN 只被动、不主动查询；无新 state0 → `insufficient`/`no_new_feedback`，`travel/peak=None`，不报 0 滑行；`first_state0_guaranteed=False`、`may_miss_frames=True`、`visibility=visible_only`；窗口末尾用新 state0 更新最终位置，>0.5° 撤销往返判据。
11. **[第一轮返工] Windows Reader 命名**：新增测试层 `test_reader_fixture.py::make_reader()` 真实短 sleep 重试构造，不替换时钟；原命令 9 模块 126 项通过；本地 runner 不再含时间 shim。
