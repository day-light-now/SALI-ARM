# SLAI 四轴软件与硬件并行任务

当前仅 J1–J4；J5 不接入控制。软件由助手实施，用户负责实物准备与检查。
用户已确认使用 DMMC02。下一步需板子版本、固件例程和电脑端接口信息；不能把它当作 USB2CAN 或假定 USB 数据线自动转发 CAN。

## 用户现在做（断电准备阶段）

1. 给 J1/J2（10010L）、J3/J4（8009P）及两端线束贴标签。
2. 发电源铭牌、通信设备型号及正反面、电机接口和线束照片。
3. 确认实物版本、配套插头针脚和原厂电压要求；现有设计以 24 V 母线为目标，但不能用旧文档代替实物确认。
4. 在电源和 USB 都断开的情况下检查极性、裸露铜线、接头固定及动力回路是否短路。禁止带电插拔，禁止把动力电压接 CAN/USB/UART。
5. 若 CAN 线束完成，断电测 H-L 电阻并记录。两个 120Ω 终端并联通常约 60Ω；不要盲目再加终端。四轴正式总线末端应在 J4，而不是未接入的 J5。
6. 检查机械臂支撑、防坠落和可触及的硬件断电装置；断电可能失去保持力，不应把切电当作防坠落措施。

暂不要求一次接齐四台，更不要求四轴联动。市电端和大电流配电由合格人员处理。
原有五轴线束文件是资料，不自动适用于当前实物或四轴总线。

## 下一阶段（照片及检查结果确认后）

1. 根据实际 USB2CAN/控制板协议决定实机传输，不把串口板误当 SocketCAN。
2. 单台连接，在确认供电、支撑、限流/保护后只读取状态和参数，先不使能。
3. 记录型号版本、CAN ID、反馈 ID、波特率、模式、位置/速度/力矩编码范围和错误码。合并总线前保证 ID 唯一。
4. 再进行单轴低增益、小角度试动，标定方向和零偏；不得直接套用 OpenArm 编码 profile。
5. 加入反馈超时、错误码、指令限幅等保护，再逐步做四轴控制。

助手不会在这些确认完成前自动发实机运动指令。

## 仿真操作

桌面入口已整理至 `SLAI机械臂控制`：启动程序在 `01_四轴仿真/01_启动`，控制程序在 `01_四轴仿真/02_控制`。

先打开桌面“启动SLAI四轴OpenArm仿真.bat”，再打开“SLAI四轴控制面板.bat”。
在浏览器访问 http://127.0.0.1:8766 。Windows 本机代理通过 WSL 标准输入输出转发，不暴露局域网端口。
输入角度后点击执行，输入本身不会驱动运动。
取消轨迹只是软件仿真取消，不是硬件急停。不要同时运行旧运动脚本抢占轨迹。
